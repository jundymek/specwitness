### Cohort & Dependencies section — required in every story, and DIFFERENT AGAIN this epic

## Step 5 — Two waves, one epic branch, and a supervisor that merges (NEW — read all of this)

Two things changed since Epic 4, and both were decided by the owner on 2026-09-03. **Verify both against the harness before you write the launch commands** — `~/.terminal-agents/README.md` and `~/.terminal-agents/CLAUDE.md` are the operative documents and they were rewritten for these features.

**Change 1 — Stage 4: the supervisor may merge story PRs into the epic.** Until 2026-09-03 the harness documented *"Stage 4 (merge) deliberately does not exist — merging is always the owner's click"*. It now exists, and this project carries the key: `SUPERVISOR_MERGE=1` is set in `~/.terminal-agents/config/projects/specwitness/project.env`, and the profile's own comment says **"This is the project Stage 4 was built to deliver faster."** That is the owner's answer to retro action item **e4-A** — Epic 4 lost ~7h43m of critical path to four ready PRs waiting overnight for a merge click, and Stage 4 is the response.

What it means for the stories you write:

- **Two axes, both required.** `SUPERVISOR_MERGE=1` in the profile (already set) *and* `--supervisor-stage 4` on the command line. Without the flag the run behaves exactly as Epic 4 did.
- **The gate is three conditions per story on this project**, because `SECURITY_GATE=1` is set: `codex_review` **and** `security_check` each `clean` or `addressed` **and fresh**, plus the **rebase verdict `clean`**. The supervisor's judgement is not among them; it may always decline and escalate, but it may never merge on its own say-so when a fact fails. (`_stage4_merge_ok`, `hooks/pre-tool-use.sh:1345`, called at 1724; thirteen refusal conditions in order, including: no `--repo`, no `--auto`/`--admin`, the target must be a branch and not the epic itself, and it must resolve to a live agent whose base *is* this epic.)
- **"Fresh" means something specific here, and it is not a timestamp.** Because this project declares `REVIEW_IGNORE_PATHS`, `verdict_is_stale()` (`lib/freshness.py:234-256`) takes its **content rule**: a verdict is fresh iff the diff from the recorded `codex_review_commit`/`security_check_commit` to `HEAD` — restricted to paths the branch itself touches — contains **zero** reviewable paths. **The clock is not consulted at all on this path.** So an agent that commits only story-spec or findings `.md` changes after signing off stays fresh, while one that touches a single line under `src/` goes stale and must re-sign. The committer-date rule is only the fallback for projects with no ignore set. Tell agents the content rule, not the date rule — the date rule is what the harness's older docs describe and it will mislead them.
- **Two of those three are the story agent's signature on its own work.** Under Stage 4, an agent's codex-review and security sign-offs are no longer paperwork ahead of a human's reading — **they may be the last thing between the code and the epic branch.** Say this in every story, in those terms. It is the single most important sentence you will write into this epic's specs.
- **`epic → master` is never permitted at any stage.** That click stays the owner's, and on this project it is the one that matters because `master` is the only long-lived branch. Every merge superman makes is appended to the epic journal, which is the owner's only account of stories they never read individually.
- **`gh pr merge --repo` and `gh pr edit --base` are blocked outright, at every stage, for every agent.** Both were live escapes from the gate on the day it was written. A base is chosen at PR creation under the base gate; `gh pr edit` without `--base` is untouched.
- **Stage 4 works on this project only because `REVIEW_IGNORE_PATHS` is declared** (`project.env:189`): `'docs/implementation-artifacts/*.md docs/findings/*.md docs/implementation-artifacts/sprint-status.yaml'`. Without it every rebase verdict would be `unknown` and every merge after the first would be refused. Two consequences worth stating in the specs: the patterns are **fnmatch globs whose `*` crosses `/`** (`lib/freshness.py:160-190`), so a spec at `docs/implementation-artifacts/epic-5-browser-verification/5.1-….md` **is** covered — story specs and findings are treated as carrying nothing to review. **`CLAUDE.md` is deliberately NOT in that set** (it is this project's scope source of truth), so a change to it is always reviewable.
