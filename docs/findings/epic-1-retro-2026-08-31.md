## 2. Post-run observations

Each: symptom → cause → why no story caught it → fix.

### 2.1 CI was red on every PR and said nothing about the code
- **Symptom:** both matrix jobs failed in 2 s with zero steps executed, on every PR.
- **Cause:** GitHub Actions refused to start jobs — account payment/spending-limit failure on a private repo. Not a code defect.
- **Why no story caught it:** story 1.1 ships CI but can only observe it after its first push; by then the failure looked like a workflow bug. Alice diagnosed it via the Actions API annotations within minutes.
- **Fix applied:** owner decision to remove the `push`/`pull_request` triggers (keeping `workflow_dispatch`) so a meaningless red check does not train reviewers to ignore CI; every agent ran the six workflow steps locally and pasted the output. **Open:** the Linux and Node-exactly-22.12 legs have never run. Two latent bootstrap defects in `ci.yml` (setup-node/corepack ordering; corepack signing-key age) were found by Codex and fixed *by construction only*.

### 2.2 A finished-but-unacted Codex review is indistinguishable from a dead one
- **Symptom:** chuck sat in `phase=committed`, `codex_review=running` for ~3 h with no events; the supervisor found no codex process and diagnosed a silent death.
- **Cause:** the review had completed (exit 0, 3 real findings) hours earlier; the agent idled between the review finishing and calling `set-codex-status.sh`, which is the only thing that clears the `running` marker. The poker did not wake him because he had no unread mail.
- **Why no story caught it:** it is a harness-observability gap, outside any story's scope.
- **Fix applied:** supervisor message woke the agent; all three findings were real and fixed. **Proposed:** the harness should flip `running` → `finished-unacted` when the review's output file appears, and the poker should nudge on that state (chuck's own suggestion: check the review output file + exit code, not `pgrep`).

### 2.3 Codex false positive against a correct depcruise rule
- **Symptom:** auto-review P1 claimed dependency-cruiser does not substitute `$1` capture groups into `to.pathNot`, so every adapter sibling import would be rejected post-merge.
- **Cause:** the claim was wrong — group matching is a documented dependency-cruiser feature. Verified three independent ways (alice's red-test, codex's own earlier clean run, supervisor scratchpad reproduction).
- **Why no story caught it:** it was caught — alice's Dev Agent Record already documented the red-test. The risk was an agent "fixing" a working rule under review pressure.
- **Fix applied:** supervisor sent evidence with an explicit "dismiss, do not change"; alice went further and pinned the behaviour with 8 automated tests (`tests/unit/dependency-rules.test.ts`). Lesson: a dismissal backed by a test beats a dismissal backed by prose.

### 2.4 Auto-review churn on a dormant file
- **Symptom:** after CI was disabled, three successive Codex auto-reviews of PR #1 each surfaced a new, increasingly speculative P2 about `ci.yml` bootstrap order, costing alice three extra commit/review cycles and the supervisor three re-verdicts.
- **Cause:** post-push auto-review re-reviews the whole branch each time; a file that cannot execute still attracts findings.
- **Why no story caught it:** process, not code.
- **Fix:** none applied; the findings were real-but-latent and all fixed. **Proposed:** allow a story agent to mark a file as `dormant` in the PR body so auto-review findings against it are logged as caveats rather than blocking re-stamps.

### 2.5 Rebase markers reported stale state
- **Symptom:** `rebase_pending` flags stayed set on pamela/rambo for ~15 min after their branches already had the new base as an ancestor; `rebase-nudge-failed` fired for agents who then rebased fine.
- **Cause:** the harness's 15-minute check window; the flag is cleared only by that check, not by the rebase itself.
- **Why no story caught it:** harness-internal.
- **Fix applied:** supervisor verified ancestry directly (`git merge-base --is-ancestor`) on every merge and ignored the flag. **Proposed:** clear the flag on the agent's next tool call if the base is already an ancestor.

### 2.6 Owner idle time dominated the wall clock
- **Symptom:** ~7 h of the ~11 h 43 m were spent with `ready` PRs waiting for a merge click; the whole of wave C was gated on PR #3 for 6.5 h.
- **Cause:** by design — merging is the owner's click and the run crossed a night.
- **Fix:** none needed; noted so Epic 2's wall-clock target is read against working time (~4.5 h), not elapsed time.

## 3. What we learned

- **Reproduce, do not trust.** Every `ready` verdict was backed by the supervisor re-running the full suite in the agent's worktree and, for CLI stories, driving the built binary. This caught nothing false in Epic 1 — which is itself the finding: six agents reported test counts that were true to the number every time.
- **Red-tested guardrails are worth more than passing ones.** Three stories (1.1 depcruise + exit-scan, 1.3 DeclaredCommand AST scan, 1.5 NFR-1 AST guard) proved their mechanical checks by planting a violation first. Two of those guards go beyond their spec and will protect every later epic.
- **The intent-sync phase paid for itself.** Seven minutes of declared intents and concrete questions (UsageError constructor shape, SCHEMA_VERSIONS shape, minimal valid config, services.ready contract) meant zero interface disputes at merge time across six stories and one shared test file.
- **Codex found real defects that tests did not:** runs-root fsync (the crash-durability guarantee 1.6 exists for), `hasResult` swallowing EACCES as exit 0, `Date.parse` accepting 31 February, parseInt saturation merging two epic ids, a `.git/HEAD`-derived baseBranch that produced a valid-but-silently-wrong config, a reachable DeclaredCommand mint. Every one of those is a "silent wrong answer" class bug — precisely what a verification gate must not have.

## 4. What went well

- Every PR body disclosed the CI situation honestly and named what remained unverified (Linux, Node 22.12).
- Spec-vs-planning-artifact divergences were flagged, never silently resolved: ADR-003 wording (`gateFailed?: string`), Q11 (nested `.gitignore`), Q27 (`ports-free` warns), kebab-case AI role keys. All four are recorded as owner decision items below.
- Agents corrected their own records when wrong (bob withdrew an `ExitCode` widening claim; chuck corrected the supervisor's "died" diagnosis with evidence).

2. **Test fakes live in `tests/fakes/`, not `src/`** (chuck's deliberate call, supervisor concurs). Epic 2+ stories import fakes from the tests tree; revisit only if it becomes painful.
3. **`domain/ids.ts` `E<n>-<NN>` criterion ids** are exported but have no consumer until Epic 2 — treat the format as frozen now.
4. **ADR-003 wording** says `gateFailed: true` + id; code and spec use `gateFailed?: string`. One-line ADR amendment pending.
5. **Doctor `commands-resolvable` rejects shell syntax** (`FOO=bar cmd`, `a && b`) by design; if Epic 3's ProcessRunner accepts any shell form, the check must learn the runner's grammar.
