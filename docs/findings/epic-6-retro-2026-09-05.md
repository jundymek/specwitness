## 2. Post-run observations

**1. CI on Linux caught a guard that reported failure on a match — the first platform-specific defect this project's CI has ever found.** Story 6.7's `pack-smoke.sh` used `tar -tzf "$TARBALL" | grep -q …`. `grep -q` exits the instant it matches, closing the pipe; GNU tar then fails writing to it and `set -o pipefail` makes the pipeline non-zero. The ubuntu job printed `ERROR: the tarball is missing dist/cli.js` **two lines above a listing containing `package/dist/cli.js`**. BSD tar on macOS exits quietly on SIGPIPE, so the identical code passed locally and in the macOS job. *Why no story caught it:* every prior epic's CI was inert, so no Linux behaviour had ever been observed; the author's local platform is macOS. *Fix:* read the listing once into a variable, removing the early-exit pipe. **Action item e3-E paid for itself inside one epic of being answered.**

**2. The same closing-pipe class appeared three times in one epic, in three different disguises.** Observation 1 is one. The second is wave 2's escalation that *a PASS can exit 1 under a closing pipe* — deliberately unfixed, because the remedy is process-global state no Epic 6 story owns. The third is that 6.7's *documentation* of the second was missing until I found it at review (§4). *Why no story caught it:* the class has no owner; it is a property of how this product writes to standard streams, and every story that meets it meets it in its own local shape. *Fix:* documented as a known limitation with the mechanism and the mitigation; the product fix remains **pending owner**.

**3. Two literal NUL bytes made a 700-line module invisible to every text tool, and eleven review rounds plus two independent codex reviews did not see it.** Story 6.6 shipped `src/report/scorecard-summary.ts` with a raw NUL as a template-literal join-key separator instead of the escape form. Runtime behaviour was identical and the design was sound. The consequence was that `grep -c "scorecard"` on the file returned **nothing** while the same file with NULs stripped returned 28, and `file` classified the module as `data`. A `grep -r` audit over `src/`, a secret scan, or any future guard built on text search silently skipped **the module that computes this product's north-star metric** — and a text tool that skips a file returns no matches, which looks exactly like a scan that passed. *Why no story caught it:* `git diff --numstat` reports 700 ordinary text lines, so the byte is invisible in review; and every automated check anyone pointed at the file was itself a text tool. *How it was found:* by the supervisor, by accident, while trying to grep for something else. *Fix:* escaped, plus `tests/unit/source-is-text.test.ts` asserting every tracked source file is text — the finding became a rule rather than a correction.

**4. A guard that fails to apply is indistinguishable from a guard that passed — four instances in a single story.** Story 6.6's author recorded all four: a `perl` plant that silently did not match, so *"nothing went red"* read as a passing guard; a parity test that matched the right number **on the wrong line** because two fields shared a value; a NUL scan using an **empty bash pattern** that "found" hundreds of offenders; and a finding-counter grep that matched her own PR text echoed back by later reports. *Why no story caught it:* nothing distinguishes "the check ran and passed" from "the check did not run" in a green result. *Fix:* each was found by **planting the defect**, never by reading. This is the sharpest single lesson of the epic and it generalises past this project.

**5. Four review rounds circled one design point, and each fix exposed the next.** Story 6.5 caps a run record's finding-id list at 200 ids; 6.6 kept treating that capped projection as the set of a run's findings. Round 1: `add` accepted an unlisted criterion while `summary` orphaned it — *"Recorded"* for a judgement no metric could count. Round 2: counting them instead let **any** valid id count, so `uniqueDefects.count` could exceed the number of findings that exist. Round 7: refusing made runs with >200 findings permanently unattributable. Round 8: the fix taught the write end and not the read end. *Fix:* stop having two sources of truth — read the authoritative list once at the CLI edge and hand it to both ends. *Why this matters beyond the story:* **had the author recorded `addressed` after round 1 and stopped, the Stage-4 gate would have accepted it**, and a north-star metric a typo could corrupt would have shipped with a clean review verdict attached.

**6. Four findings in one story were defects introduced while fixing earlier ones.** 6.6 again: a fix that printed the parser's full message — so ADR-008 §5's field names reach the operator — put untrusted text on a terminal for the first time, and the next two rounds found terminal-escape injection at both sites. Reproduced against the built binary, a crafted JSON key coloured the output and **forged a line of its own inside a metrics report**. 6.7 has the same shape at a smaller scale. *Fix:* both sites escape C0/DEL/C1; `--json` keeps the original because `JSON.stringify` escapes control characters itself.

**7. A rebase orphans a recorded verdict, and nothing in the harness says so.** Wave 3's 6.6 carried `codex_review` and `security_check` naming a SHA that her rebase had rewritten: `git merge-base --is-ancestor <sha> HEAD` exited 1. The status fields still rendered as recorded verdicts. This is a **third shape** of wave 2's "a status line that reads true and is not" — distinct from staleness (the verdict is not old, it is unreachable) and from the auto-review clobbering. Her own framing: *"a verdict's freshness is not only about what changed after it, but about whether the commit it names still exists."* *Why no story caught it:* the freshness rule is content-based and answers a different question. *Fix:* none in code; found by the supervisor and reported. **Action item e6-A.**

**8. The auto-review classifier is content-blind in BOTH directions, and the inverse cost more than the original.** Wave 2 recorded e3-A as the classifier reporting "no findings" over real findings, twelve times across five agents. Wave 3 added: it reported `auto_review_findings` for a run that **echoed its own prompt file** instead of producing a report; it reported findings over a report concluding *"no actionable correctness defect was identified"*; and it reported findings over **a commit that changes one markdown file**. It was also **right once** when a manual run was clean — two reviews of one head disagreed and the auto side's three findings were all real. *Consequence:* 6.7's author concluded the notifications were noise and stopped opening the logs, leaving three real documentation defects unread — he was applying e3-A to `clean` verdicts only, half a rule. *The sharpest form,* from 6.6's author: **the label is unreliable on inputs where being wrong is trivially detectable, and an agent who trusts it there has no way to notice, because the correct action — read the log — is the same action that reveals the label was wrong.**

**9. Running two independent reviews over one head found three real defects a single review missed.** Wave 3's 6.6 ran a manual `codex exec review` and the harness auto-review over the same commit; they disagreed, and the auto side's findings were all real. This is cheap evidence for a practice nobody had proposed.

**10. Documentation produced its own defect class, in the place it matters most.** 6.7's first draft of the AD-3 boundary wrote *"nothing an AI provider returns can introduce a command, a flag or a shell string."* Command and shell string are true; **flag is false** — `src/surfaces/shell.ts:35` records that a shell probe is the one place a provider-authored artifact chooses arguments to a real command, and on an AI-compiled plan the same provider writes the allowlist that bounds it. *Why no story caught it:* it is prose, and prose has no test. *Fix:* corrected in both documents with the mitigation named — compile the plan, read it, commit it, verify with `--no-ai`. **A security overclaim in a document telling people to grant a privilege is the worst possible instance of Epic 5's "true of the case in front of the author, false in general".**

## 3. What we learned

1. **Plant the defect; do not read the guard.** Four vacuous guards in one story, every one green. A guard nobody has watched fail is not evidence.
2. **Re-review after acting on a review, not only before.** Four rounds in one story found defects introduced by the immediately preceding fix. The gate cannot see this and does not claim to.
3. **A verdict names a commit, and a rebase can make that commit unreachable.** Check reachability, not only content freshness.
4. **Neither auto-review label is evidence, in either direction.** Open the log, count `Review comment:` blocks, read the conclusion — and exclude `+`-prefixed diff lines, because a branch whose diff *discusses* reviewing produces false positives on that marker.
5. **CI on a second platform is worth what three epics of argument said it might be.** One epic of execution, one real defect that no local run could produce.
6. **Two independent reviews over one head are cheap and they disagree usefully.**

## 6. Next-epic readiness (Epic 7 — first real dogfooding)

Epic 7 gates a real epic and reads 6.6's summary; the brief's §54 hypothesis stands or falls on that number. What it inherits:

- **The measurement exists and is honest by construction.** The north star is a count object rather than a rate, unattributed findings are counted and printed on the second line, skipped records are reported per source with the unknown field names, and every rate carries its denominator. A rate over a zero denominator is `null`, never `0%`.
- **`setup.install` is the one thing that will bite immediately** if the first real project declares it. A real project's gates need installed dependencies. Read 6.11 before wiring the first contract.
- **The friction question the PRD deferred is now a recorded choice**, not an open one: flag-driven, prompt-free, one finding per invocation, with the reasoning written so Epic 7's data can contradict it. **If the annotation simply never happens, that is the finding**, and it will show as a large `unattributed` count.
- **The corpus is 16 fixtures and the runner drives the real built CLI.** A regression in the verdict path fails a fixture; since 6.10, so does a regression in what a run *observes*.

## 10. Three waves, Stage 4, and what the owner did not see

Eleven story PRs merged without the owner reading one of them. Two carried a supervisor `needs work` first, and both findings were real: an undocumented exit-code limitation that would have shipped a table wrong in a case somebody had already measured, and two NUL bytes that made the north-star module invisible to every scan anyone could point at it.

**Neither was found by a test, a gate or a review.** The first came from reading a spec clause against a document; the second from a `grep` that returned nothing when it should have returned 28. That is the argument for the role, and it is also its warning: both were one careless pass away from merging clean, and this epic's own evidence says the instruments would not have caught them.

The number I would put in front of Epic 7 is 6.9's author's, from wave 2, unchanged by anything wave 3 found: **product defects 0, instrument defects 22.** Epic 6 built the apparatus that measures whether this product finds real defects. Almost every defect it produced along the way was in the apparatus.
