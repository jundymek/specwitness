## 2. Post-run observations

Each is symptom → cause → why no story caught it → fix.

### 2.1 The cohort stalled for 3 h 42 m and nothing in the system noticed

**Symptom.** Twice, every agent stopped mid-turn and stayed stopped after the limit reset — 71 minutes the first time, 2 h 27 m the second.

**Cause.** The owner's usage limit cuts a turn wherever it lands, so agents stop in `coding`/`pushed`/`tests-passed` — never in `inbox-pending`, the only phase `inbox-poker.sh` pokes. The poker also (correctly) withholds Enter from a pane showing a usage-limit notice. So after the reset, nothing wakes anyone.

**Why no story caught it.** It is not in any story's scope; it is a property of the harness plus the account.

**Fix.** Recorded as H-1 in `epic-2-harness-defects-2026-08-31.md` and handed to the harness repo. Both times it took a human-authorised keystroke from the supervisor to clear. **This is now the single largest cost in the epic — larger than every defect, rebase and review round combined.**

### 2.2 A rebase nudge reopened three agents whose stories were already merged

**Symptom.** pamela was reopened from `done` twice, bob once, after their own PRs had merged. bob then did 45 minutes of work that had nowhere to land.

**Cause.** The notifier fires on `epic-updated` without checking whether the recipient is `done`, or whether the recipient's *own* PR is the commit that moved the base — and the recipe says to rebase *"immediately and verbatim, without waiting for the operator"*. For a merged agent that instruction can only conflict or force-push after merge.

**Why no story caught it.** Harness behaviour, invisible from inside a story.

**Fix.** H-3, with pamela's two proposed fixes verbatim. The record explicitly narrows the fix to the *nudge*: arnold was reopened by a **peer message** and answered a real cross-story question two minutes later, which is the inbox gate working. Suppress the nudge for merged agents; never the mail.

### 2.3 `git rebase` is the wrong command after a squash merge, and the harness tells agents to run it

**Symptom.** bob's rebase conflicted on all five of his already-merged commits.

**Cause.** A squash merge means the agent's commits are not ancestors of the new base — content matches, patches do not. The nudge text says plain `git rebase origin/<epic>`.

**Why no story caught it.** Same reason.

**Fix.** H-4 carries the working recipe: `git rebase --onto origin/<epic> <last-merged-sha>`. **Confirmed live during closure**: the supervisor's own branch conflicted on every commit under a plain rebase and replayed five commits cleanly with `--onto`.

### 2.4 The pre-PR gate reveals one failing precondition per attempt

**Symptom.** pamela's `gh pr create` was refused four times, each for a different, individually knowable condition.

**Cause.** The gate returns on the first failure instead of reporting all of them.

**Why no story caught it.** Harness.

**Fix.** H-12. Worth more than its round-trips: the repeated command in the scrollback is what led the **supervisor** to misread her pane as a pending second PR and send an unnecessary STOP. A serial gate does not only waste attempts; it makes a pane unreadable to whoever is diagnosing from outside.

### 2.5 Codex credits ran out mid-review on the last story, and the gate could not tell

**Symptom.** dolph's final auto-review died with `auto_review_failed exit=1` on a usage limit. He recorded a verdict 48 seconds later, which the pre-PR gate accepted because it was newer than his last commit.

**Cause.** The freshness rule checks *when* a verdict was recorded, never *whether the review that produced it completed*.

**Why no story caught it.** The gate is harness-side, and dolph did the right thing anyway — he recorded `addressed` rather than `clean` and put the caveat in the PR body **before** the supervisor asked.

**Fix.** Recorded beside H-11/H-14. In the meantime the supervisor hand-reviewed the one commit Codex never saw (`43b4e09`, 45 lines) and reported it as such in the verdict rather than letting a fresh-but-incomplete verdict pass silently.

### 2.6 Five agents hit a spec instruction the hook forbids

**Symptom.** rambo, arnold, dolph, chuck and bob all took `set-depends-on/agent-wait is not allowed before cohort intent-sync completes` blocks in their first minutes.

**Cause.** Specs 2.4–2.7 say to run `set-depends-on.sh` "immediately after reading this spec"; the intent gate forbids exactly that until sync completes.

**Why no story caught it.** The contradiction is between the story template and the hook, and each agent meets it once, alone.

**Fix.** H-10 — move the instruction after the intent-sync step in whichever template generates that block.

### 2.7 A test-isolation defect surfaced three times and belongs to nobody

**Symptom.** alice, bob and arnold each saw an unexplained single-test failure in a full run; alice reproduced it deterministically.

**Cause.** `tests/unit/dependency-rules.test.ts` writes **fixed-name** scratch modules into the real `src/` and cruises the whole tree, while the harness runs `pnpm test` in the same worktree for every push.

**Why no story caught it.** The file belongs to story 1.2. Stories 2.1 and 2.2 both extended it and both correctly declined to patch a shared defect in parallel branches.

**Fix.** Story **2.8** was written for it (supervisor, with the owner's agreement, PR #12) and is `ready-for-dev` and unassigned. The harness half is H-8.

## 3. What we learned

1. **A test written to satisfy a supervisor's instruction found a live bug that six Codex rounds had missed.** alice's D3 dedent was defensible, but the "deeper indentation survives" half was asserted by nobody. Writing that assertion revealed that any criterion with an indented sub-paragraph was being silently **truncated** — losing the paragraph, a fenced sample, and the following criterion. The lesson is not "add more tests": it is that *the unasserted half of a decision is where the bug lives*.

2. **Manual testing found the highest-value defect of the epic, and no automated reviewer could have.** dolph drove the real binary through a pty; Ctrl+D at the amend prompt printed *"this is a SpecWitness bug — please report it"* for an ordinary way to back out. It survived 27 unit tests, 4 built-CLI integration assertions and nine Codex rounds, because the interactive path is reachable in tests only through an **injected** predicate — and an injected reader never aborts. Keep the manual-testing gate; it is not ceremony.

3. **Reusing a probe is not enough — the judgement over the probe has to be shared too** (dolph). He argued successfully for one shared capability probe so doctor could not drift from a real invocation, then judged `capable` with his own predicate: a codex missing `--output-last-message` was reported READY and would have refused at the point of use. Epic 3's verify path will face the same shape when it renders pipeline results.

4. **ENOENT is a symptom with at least two causes.** Under execa 10 with `reject: false` a missing binary *resolves* rather than throwing, and an invalid `cwd` raises the identical error. It bit pamela's runner and, one layer up, doctor's merged `runGit` — where `notFound` had been false for every input since story 1.5. A first fix made it *worse*: a vague wrong answer became a confident one, telling operators to install a `git` they already had.

5. **Intent-sync buys correctness only if consumers verify against merged source.** Twice, reading the shipped code beat trusting a peer's summary: chuck caught pamela's stale `jsonSchema` instruction, and dolph caught the `runGit` claim by reproducing it. Both summaries were written in good faith and had simply gone stale. **Recommendation for Epic 3: keep intent-sync, and add an explicit expectation that a consumer re-checks the shape against merged source before building on it.**

6. **The supervisor's own artifacts need the same gate as an agent's.** Codex found seven things in the 2.8 spec across four rounds — including one contradiction the supervisor *introduced while fixing another*, exactly the class ("a fix that quietly narrows what it claims to guarantee") the supervisor had flagged in two PR reviews the same day. All seven were caught by the gate, none by the supervisor's judgement.

The mechanism that mattered most was pamela's refinement of dolph's proposal: rather than splitting ownership of one test file, she restructured so the two stories shared **zero `expect()`** — a stronger property than "we coordinated".
- **Cross-story ownership held under pressure.** rambo found he had duplicated arnold's five-line `contextFiles` format. He did not ship the duplicate and did not silently edit a merged file: he raised it, got written agreement with five conditions, and met all five. The supervisor verified each against the diff — arnold's tests are untouched, the added assertion sits *beside* his, mirrored in both suites so a wording change goes red on both sides.
- **Agents reported defects outside their own scope instead of fixing them in parallel.** The `runGit` ENOENT bug, the forking-timeout hang, the concurrent-test flake, the stale addendum §B — all reported, none patched four different ways in four branches.

## 5. Technical debt carried forward

1. **Orphaned descendants are not reaped when a spawned child forks.** Detection is fixed (`run()` always settles and classifies); reaping needs `kill(-pgid)`, deferred to Epic 3 story 3.2. **Concrete evidence: nine orphaned `sleep 3600` processes** were left on this machine by 2.5's own timeout test and reaped by hand. Epic 3 gate commands (`npm test`, `docker compose up`) are precisely the child-spawning class.
2. **`roadmap.md`'s EPIC 3 wave-A line still reads "3.2 (infra/process-runner, run-store manifest side)" unqualified**, while 2.3 created that file minimally and 3.2 owns the lifecycle half. Needs the line amended to "lifecycle **extension**" or an ADR. Raised by 2.3, restated by the supervisor. **This is the item that keeps (1) findable.**
3. **`meta.provenance.model` and `providerCliVersion` are `null` on every path today.** Codex cannot report a model at all, and wiring the value through from adapter capability results belongs after 2.6, whose branch was cut before the adapters merged.
4. **Addendum §B is stale**: it records "No first-class JSON-Schema-constrained output flag observed" for claude, but 2.1.251 lists `--json-schema`. Deliberately unused (outside the probed baseline; a CLI-side constraint can never replace the zod gate) — but the document should say so.
5. **Story 2.8 is written and unassigned.** Prerequisites all merged; file-disjoint from everything else in flight.
6. **A residual write race in `--amend`** (dolph's D15): the window that mattered — the unbounded human-at-the-prompt interval — is closed by a byte-comparison re-read; a microsecond window before the rename remains. Closing it needs a lock or CAS, which ADR-005 defers to v2+ alongside signing.
7. **The Linux `MAX_ARG_STRLEN` figure (128 KiB per argv element) is documented, not verified.** Both adapters send prompts over 64 KiB on stdin because of it. No Linux host in any worktree; CI disabled.
8. Epic 1's debt items 2–5 carry forward unchanged (fakes in `tests/`, frozen criterion-id format, ADR-003 wording, doctor's shell-syntax stance).

### 5a. Two defects found by the post-closure Codex pass

Once the account's Codex credits reset, the supervisor ran the review that the credit limit had prevented — over the whole epic diff against `master`, not just the two commits it was meant to cover. It found nothing wrong with either of those, and **two P2 defects elsewhere in already-merged code**. Both are recorded here rather than fixed, because the epic had closed; neither blocks the integration merge.

**(i) `fenceMask` closes a fenced block on a tagged inner fence — `src/ingest/bmad-v6/markdown.ts` (story 2.1).** The close condition checks the marker's kind and length but not that the rest of the line is blank. CommonMark forbids an info string on a *closing* fence, so ` ```typescript ` inside an open ``` block is content; SpecWitness treats it as a close.

Confirmed by execution, not by reading — a probe over `fenceMask(['```', '```typescript', '## Acceptance Criteria', '```', '### Story 9.9'])` returns the mask **inverted** at both ends: the `## Acceptance Criteria` *inside* the example is exposed as structure, and the real content after the true closing fence is masked as fenced. That is both halves of the hazard story 2.1's own round-4 finding was about — a fenced `## Acceptance Criteria` can truncate a real section, and genuine structure after the block becomes invisible. Reaching it needs a document that opens a nested example without lengthening the outer fence, which is malformed-but-plausible markdown. **The fix is one clause**: require the remainder of a closing-fence line to be whitespace.

**(ii) The atomic contract writer reports a failed write after the rename has already succeeded — `src/authoring/contract-file.ts` (story 2.6).** `syncDirectory(directory)` runs *after* `rename`, inside the same `try`. If the directory sync fails for anything the code does not tolerate, the `catch` raises `could not write .specwitness/contracts/<epic>.yaml` — while the file has in fact been replaced. Rare (a directory fsync failing after a successful rename), but the consequence is a lie about state in the module whose entire purpose is that the state is never ambiguous: the operator believes nothing changed, and the previous contract is gone. **The fix is to treat post-rename failures as a distinct, non-fatal condition** — the write committed; only the durability barrier did not.

**Both are cheap to fix and neither is urgent.** They are listed here so Epic 3 inherits them findable rather than as folklore: (i) matters because Epic 3 ingests more real epics, and (ii) matters because Epic 3's verify path reads the file this writer produces.
