# Epic 3 retrospective — isolated deterministic verification

Written by the supervisor of `epic/3-isolated-deterministic-verification` (superman), 2026-09-01, after all eight stories and every follow-up merged. Sources: the 17 PR bodies (#21–#37), the per-PR verdict blocks in the supervisor's reports file, the events log, and the supervisor's own reproductions (every story PR's suite re-run in the author's worktree; the integrated epic head rebuilt from a clean clone with all four gates green and the exit table exercised live).

## 1. Delivery summary

- **8 stories, 17 squash commits** on the epic branch: 8 story PRs (#21–#24, #27–#29, #37) and 9 follow-up/docs PRs (#25, #26, #30–#36). Every PR carried a supervisor verdict before its merge click except #24 (see observation 6).
- **Planned vs actual merge order.** Roadmap waves held: wave A (3.8, 3.3, 3.1, 3.2) merged first, wave B (3.5, 3.6, 3.4) after, 3.7 last. Within wave A the fully-independent 3.8 landed first (36 minutes from cohort launch to merge), as its spec intended.
- **Test growth:** the suite grew from 1359 tests at Epic 2 close to **2191 passed | 3 skipped (108 files)** at epic head — verified by the supervisor on a clean clone, alongside lint/typecheck/build and a live run of the exit-code table (0/1/2/3/64 all exercised through `dist/cli.js`, most by the integrated verify suite, 64 and two 3-variants additionally by hand).
- **Wall clock:** cohort launch 2026-08-31 20:10Z, final merge 2026-09-01 ~18:16Z (~22h), of which **~7.5h were three subscription session-limit freezes** (21:09–06:25 split across the reset, 07:57–10:20, 13:06–15:20) and ~1h a codex quota outage. Productive time was roughly half the elapsed time.
- **Zero interface disputes at merge, again.** Intent-sync produced written seam contracts in the first 20 minutes; the five cross-file edits that later proved necessary all travelled with compile-order justifications and the file-owner's quoted written consent.

## 2. Post-run observations

Each as symptom / cause / why no story caught it / fix.

**(1) Three session-limit freezes cost ~7.5h.** Symptom: the whole cohort mid-turn goes silent; sessions sit at an empty prompt after the reset with nothing to wake them. Cause: eight parallel sessions burn a subscription usage window several times faster than one operator. No story could catch it — it is an account property. Fix applied during the epic: the supervisor read the pane banners, waited for the reset, and woke sessions via tmux with resume prompts (a second Enter was sometimes needed; one wake needed a fresh prompt). Durable fix is the owner's: stagger waves, raise limits, or give the harness a limit-aware scheduler (action C).

**(2) The codex auto-review classifier reports clean over non-clean runs — three sightings, two flavours.** Symptom: `auto_review_clean` over a log carrying an unaddressed P1 (arnold); over a suite summary of 11 failures (rambo); over a completed report with a live P2 and a negative verdict line (chuck). Cause: the classifier keys on codex exit 0, not report content — and (chuck's mechanism find) a completed report can land in the task output file while `codex-auto-review.log` holds only an earlier abort, so even the anchored-grep discipline reads zero for a run that has findings. Why no story caught it: harness code; the cohort correctly refused to patch it five separate times. Mitigation that held: every agent signed off from the actual report, never the status line — three agents demonstrably caught real findings the classifier had hidden. Fix is the owner's (action A).

**(3) Three independent sources of false red tests compound with (2).** H-8 (the harness runs `pnpm test` in the agent's worktree concurrently — reproduced by rambo), the supervisor's own dist/-race during a review (two vitest+tsup runs sharing one `dist/`), and the codex sandbox (`workspace-write` cannot read the process table, so `pgidOf` tests fail there — chuck). False reds plus a classifier that hides real findings is a trap for the diligent: readers of the log chase phantoms, non-readers ship past real failures. bob and rambo's joint measurement (PR #31) is the model: falsified hypotheses labeled as falsified, the unexplained left as "unexplained". Fix: review runner executes the suite in a throwaway copy (action B).

**(4) A squash-merge dropped a reviewed commit.** Symptom: #23's merge landed at a commit before alice's last push; a reviewed, signed-off fix (`removeEmptyContainer`) silently did not ship. Cause: a push racing a merge click — ordinary in a supervised cohort. Caught because alice compared the merged tree against her branch head; restored by cherry-pick in #25. Cohort rule adopted and used thereafter: **after a squash-merge, verify what landed** (`git show <base>:<path> | grep <marker>` per fix). The supervisor adopted the same rule for verdicts (a verdict names the head commit it covered).

**(5) Merged code contradicted two recorded decisions, found only by running the built binary.** A `verifiability: human` criterion auto-PASSed at exit 0 (Q39's first NEEDS_HUMAN trigger unreachable — `verifiability` dropped at the integrity stage) and every stage hint was discarded (a tampered-contract refusal printed zero stderr bytes, inviting exactly the `--freeze` laundering ADR-005 exists to prevent). Neither was reachable by any unit suite because each lived in a seam between merged stories. Both were found by 3.7 wiring the real command, escalated with measurements, and fixed by the owner story (#32). The generalisable lesson: **an integration story's job is to run the product, and seam defects are what it is for.**

**(6) The supervisor's one wrong `ready`.** #24 was stamped ready four minutes before its head's auto-review finished with a live P1, and the chime led to a merge click 75 seconds before the correction landed; the P1 (a real `clean`-vs-active-run race) then had to be fixed forward as owner-ordered follow-up #26. Rule adopted and applied for the rest of the epic: **no ready stamp while codex is not in a terminal state for the verdicted head.** No later verdict repeated the mistake.

**(7) The redaction module cost six leaks and a quadratic blowup before it settled — all caught pre-dogfooding.** chuck measured the quadratic backtracking (1 MB ≈ 25 min), arnold reproduced it within a few percent, pamela fixed it with a measured bound (1 MB → 925 ms) and, adding one required field, worked through six leak shapes ending in the right design: **shell context is declared by the caller, never inferred from text** (an apostrophe in prose is indistinguishable from a shell delimiter; undeclared input fails closed). The leak shape worth remembering: output containing `[REDACTED]` with the secret still beside it survives review in a way a raw leak does not.

**(8) Spec defects surfaced and were handled correctly.** 3.3's spec self-contradicted (`RunResult.evidence: EvidenceRef[]` in a task bullet vs bounded-inline-content requirements everywhere else) — resolved to `Evidence[]`, corroborated independently by two consumers, endorsed by the supervisor. The §10 supervisor-brief delta stated `docs/findings/` does not exist while every spec cites files in it. Early PR titles (#23, #25) were prose because the authors had not connected that a squash-merge promotes the title to the epic-branch commit subject; the convention now lives in this record (action H) and the last six PRs got it right unprompted.

## 3. What we learned

1. **Escalate-not-patch scaled.** Five cross-file defects were found by non-owners and every one was routed to its owner with evidence; the two carried-in-peer-PR test edits travelled with compile-order proofs and quoted consent. Nobody patched harness code once in eighteen temptations. The convention costs a message and saves a fork.
2. **The compile-order rule for test edits is now precedent:** a test change made necessary by a source change travels in that change's commit, with the file-owner's written review; there is no order in which the owner can go first when the fixture references types that do not exist yet.
3. **A guard must encode the distinguishing fact, not a proxy for it** — pamela's redaction scan (declared shell context), rambo's mirror guard (structural equality after `keyof` was caught as a proxy), chuck's shim fix (wait for the event, not the wall clock). Three agents converged on the same sentence from three directions.
4. **Sign-offs are grounded in artefacts, not signals**: the log, then the actual report of that run, never the status line — and a finding can be correct through a faulty premise (chuck's triage note), so a wrong premise is not grounds to dismiss.
5. **Follow-up PRs beat scope creep.** Nine follow-ups, most turned around in minutes (alice's mkdtemp wrap: 4 minutes from instruction to open PR), each one item, each red-first. The epic's final state has no known gap that is not either fixed or named with an owner.

## 4. What went well

- Intent-sync again produced zero merge-time interface disputes across eight agents, and this time the published-shape corrections (SHAPE UPDATE 1/2) caught a secret-persistence hole and a redaction leak **before** the first consumer merged.
- The wave plan held with no idle deadlocks; the one potential deadlock (3.5↔3.6 renderer wiring) was escalated instead of settled privately and resolved by a sanctioned follow-up with conditions that were then met exactly.
- Red-first discipline was near-universal and audited: mutation-verified guards, seen-red flake fixes, and PR bodies that recorded reversals ("my first fix was wrong because…") as first-class content.
- The supervisor reproduced every story PR's test claim in the author's worktree and caught one real red suite (a mid-fix working tree) and one premature ready (its own).
