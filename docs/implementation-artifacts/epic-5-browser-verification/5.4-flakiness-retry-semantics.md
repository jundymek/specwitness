## Dev Notes

### Goal & Context

**The mechanism is merged, proven and correct. What is missing is a way to ask for it.**

`RetryPolicy` has existed since Epic 4 as `(surface: ProbeSurface) => number`, injectable only by tests, resolving in production to zero for every surface. `deriveCriterionResult` implements the flake rule and has been proven across three surfaces and a conformance suite: *the final attempt decides; `flaky` marks a pass that happened only on retry; a run that passed then failed is a failure, not flake.* Epic 4's retro closed with the observation that this leaves **nothing left to design** — the ADR that adds the field has no open questions.

So this story is plumbing plus visibility, and the visibility half is the part that matters. FR-32 and NFR-5 exist because the failure mode of retries is not technical, it is **epistemic**: retries make a verification tool *less* trustworthy the moment they are invisible, because a green run stops meaning "this worked" and starts meaning "this worked eventually, and nobody will ever know." That is why the AC demands the counts in three places rather than one, and why `terminal.ts`'s existing comment says *"a renderer is the last place that visibility can be lost."*

**The defect shape to fear is the one Epic 4 called its worst:** a plausible-looking wrong answer. A retry that launders a real failure into a flaky pass reads as green and is wrong, and nothing downstream can tell. Epic 4's instance of that class was found by review rather than by its author — plan for the same here.

### Failure modes (what "wrong" looks like here)

- **⚠️ A retry that launders a real failure into a flaky pass.** Epic 4 retro §2 observation 5's shape: *a verification tool that returns a plausible-looking wrong answer is the worst failure this product has.* Reads green, is wrong, undetectable downstream. **This story's headline risk.**
- **Retries on by default.** AD-9 and Q43 say opt-in, default 0. A default retry silently converts every flaky environment into green.
- **An unbounded retry count.** A typo spends an afternoon.
- **Marking pass-then-fail as flaky** — softening a real defect into noise, which `criterion-result.ts:210-212` explicitly refuses.
- **Retrying an `error` into a `pass` and calling it flake** without recording that the environment failed. A retry does not convert infrastructure into product.
- **Discarding non-final attempts.** The derivation only reads the last one; if nothing else keeps the others, the evidence a human needs in order to *use* the flake marker is gone.
- **A flaky count that disagrees between terminal and JSON.** AD-11's drift, in the one field whose entire purpose is visibility.
- **Re-implementing the flake rule** anywhere outside `deriveCriterionResult`.
- **Retry orchestration inside an executor.** `flaky` becomes wrong and the attempts vanish.
- **A breaking schema change** that stops last week's `result.json` parsing.
- **Slow tests that collide under H-8.** Real-time retries multiply the cost on the reviewer's machine.
