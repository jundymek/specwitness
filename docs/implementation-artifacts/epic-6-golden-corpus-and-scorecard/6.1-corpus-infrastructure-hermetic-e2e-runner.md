### Goal & Context

**This is the story where SpecWitness stops being verified by its own authors and starts being verified by evidence they cannot edit while looking at the result.**

Five epics have shipped 3452 passing tests. Every one of them was written by the same agent that wrote the code it tests, in the same session, with the ability to adjust either side until they agreed. ### Codex review findings, and what they changed

Six review rounds, **twelve findings, all twelve real, all twelve fixed**, each with a test
seen red against the pre-fix code. Recorded in full because the pattern is the story's own
subject, and worth naming for wave 2: **every one was a guard that looked correct and
inspected less than it appeared to.** That is what this story is about, arriving in this
story's own code, twelve times. If something in the runner looks over-engineered, that is why.

#### Round 6 — two findings (one P1, one P2)

13. **A symbolic link inside a fixture defeated every guard at once (P2 by label, and the
    widest of the twelve).** `cp(..., { recursive: true })` preserves a link into the
    executable project while an `isFile()` walk skips it — so a link would be RUN and never
    READ: no port substitution, no loopback scan, no fetching-tool scan, no credential-store
    scan, and no content in the tree hash, which would also let the immutability guard report
    a fixture unchanged while what actually runs had changed underneath it. Refused at the
    directory walk so every caller inherits it, and refused rather than resolved: a corpus
    fixture must mean the same thing on every machine, and a link's target is by definition a
    fact about the machine.
14. **The new AD-11 check skipped a run that printed a document and persisted nothing (P1).**
    Comparing only when both exist meant a regression that stopped writing `result.json`
    would sail through, because the fixture's outcome still comes off stdout — the AD-11
    check I had just added, defeated by the same "inspected less than it appeared to" shape
    as the nine before it. The two states are told apart by whether stdout parsed: an edge
    refusal prints nothing and stores nothing, and stays legitimate.

#### Round 5 — three findings (one P1, two P2)

10. **An `infraError` expectation with no document verified only that SOMETHING was on
    stderr (P1).** The classification is printed nowhere and exit 3 is identical for all
    five — I verified this directly against a tampered contract, which exits 3 with empty
    stdout and **no run directory at all**, so `infraError: 'integrity'` cannot be read back
    from anything. A fixture expecting `provider` with only `ERROR:` pinned would have stayed
    green while the CLI reported `config`: the classification confusion FR-22 exists to
    prevent, arriving through the corpus meant to pin FR-22. The message is now required to
    be specific, and a bare `ERROR:` is refused. Length is an honest proxy — nothing
    mechanical can decide whether a sentence names an integrity failure, but it can refuse
    evidence that names nothing.
11. **A `--json` fixture could pass with broken stdout (P2).** The runner fell back to the
    stored `result.json` when stdout did not parse, so a broken machine-readable document
    was invisible. Turned into a positive assertion instead: when `--json` is requested and
    the run persisted a result, stdout and `result.json` must be the **same bytes** (AD-11,
    Q53) — compared raw, because a parsed-and-reserialised comparison would pass while the
    byte sequence differed, which is exactly what the invariant is about. Both shipped
    fixtures satisfy it, so the corpus now pins AD-11 as a property rather than a stated
    intention.
12. **URL schemes and hosts were matched case-sensitively (P2).** `HTTPS://EXAMPLE.COM` is
    the same request as the lower-case one, and a guard bypassable by pressing shift is not a
    guard. One shared host extractor now serves both the static scan and the runtime evidence
    check, so the two cannot drift apart.

#### Round 4 — the auto-review of the fixed tree (one P1)

9. **The network-command guard only inspected `run:` lines.** A YAML block scalar walks
   straight past it: `run: |` followed by an indented `curl` puts the command on a
   continuation line the filter skipped, so a fixture could have fetched while the
   hermeticity assertion stayed green — the same shape as finding 7, one layer in. Rather
   than teach a line scanner to track YAML continuations, then heredocs, then shell line
   continuations, the filter is gone: every line of every file in a fixture is scanned. A
   fixture is a few dozen hand-written lines and there is no line of one where `curl`
   belongs. That also closed a hole the narrower version never covered — a gate SCRIPT that
   fetches, which is not a declared command at all. The patterns were tightened in the same
   change, because `\bcurl\b` matches inside `commands/curl-parser.js` (`/` and `-` are word
   boundaries) and a false positive here teaches the next author to distrust the guard.

#### Round 3 — the explicit review (one P1, one P2)

7. **The localhost-only guarantee was static only (P1).** The suite scanned checked-in text
   for literal `http(s)://` authorities, so a fixture could have assembled a hostname at
