Clarifications (detail only, no weakening):

- **⚠️ WHY THIS STORY EXISTS, IN ONE PARAGRAPH.** Five merged integration suites — `tests/integration/surfaces/browser.test.ts`, `browser-security.test.ts`, `browser-adaptation.test.ts`, `browser-dispatch.test.ts`, `browser-combined-evidence.test.ts` — sit behind `describeWithBrowser` (`tests/integration/surfaces/helpers/browser-fixture.ts:114`), which calls `describe.skip` when `BROWSER_ENVIRONMENT.ready` is false. **`@playwright/test` is an optional peer** (a binding spine decision, `ARCHITECTURE-SPINE.md:153`), so `pnpm install --frozen-lockfile` does not bring it and nothing downloads chromium. **On every CI runner, all five skip and the job goes green.** Epic 5's retro §9 names the same gap from the other side: *"a real browser download — performed by no gate on any platform in this epic; provisioning is proven against an injected `ProcessRunner`."* **You are closing it.**
- **AC2 — non-blocking is a deliberate decision, not timidity, and it has a stated end.** Browser suites are the most flake-prone thing any CI has, and a **required** check that goes red for unrelated reasons trains people to ignore red — which is the precise failure this product's whole exit-code taxonomy exists to avoid. So: **non-blocking on introduction**, and **your PR body proposes the promotion criterion** (a concrete one — e.g. "green on N consecutive runs over a week, then flip to required"). **The owner decides when; you decide what would justify it.** A non-blocking check with no promotion path is a check nobody will ever look at.
- **AC3 is the most valuable thing in the story and the easiest to skip past.** Story 5.1 wrote a provisioning path — resolve a cache, install `@playwright/test`, download chromium — and **it has never provisioned anything.** It is proven against an injected `ProcessRunner` and nothing else. The cheap way to build this job is `pnpm exec playwright install chromium` and never touch SpecWitness's own code path. **That is an acceptable answer, but only if you state it**: which path ran, which did not, and what therefore remains unproven. **Exercising SpecWitness's own provisioning is worth real effort** — it is the only way that code is ever tested before a user meets it.
- **Read story 5.1's merged module header before you touch anything** (`src/infra/playwright-env.ts`). It names the exact cache location per platform, states that `PLAYWRIGHT_BROWSERS_PATH` is **input, not authority** and is refused if it points under the project root, and records the resolution order (project → SpecWitness cache → absent, where **absent is a first-class value, not an exception**). **A CI job that sets an environment variable carelessly can silently change which of those three branches runs**, and then you would be testing a path no user takes.
- **⚠️ AC4 IS THE REAL RISK OF THIS STORY, AND THE SUITE'S OWN AUTHORS SAID SO.** `browser-fixture.ts`'s header: *"A leaked browser tree is the worst leak this product can produce, and it lives until reboot."* Every fixture is self-limiting for that reason, because **when a test run is killed outright, no `afterEach` executes at all** (Epic 4 retro §2 observation 8). **This epic is the first time this product's process-group and signal code runs on Linux at all**, and you are putting the heaviest process tree it can spawn on top of that, on a shared runner. **Verify reaping explicitly** — check for surviving processes after the job, including after a cancelled run — and **state the evidence.** "The tests passed" is not evidence about what survived them.
- **`browser-security.test.ts` is in your set, and it is the reason to care most.** A security suite that has only ever run on its author's machine is a security suite with one data point. **Report its result specifically**, not merely as part of a passing total.
- **Findings are the output, not the obstacle.** If a browser suite fails on Linux, **that is the story working.** Report it with evidence. **Fix it only if the fix is small and obviously correct** — these are merged suites owned by an Epic 5 author who is gone, and a hurried change to a security suite to make CI green is precisely the wrong instinct. Escalate anything larger with a written recommendation.
- **Cost is a real constraint and you own it.** Chromium is roughly 150MB; a cache miss costs minutes on every run. **Cache the browser bundle** (the existing workflow already caches the pnpm store and its comments record two real traps in doing so — read them). **Report the job's wall-clock time**, cached and uncached, in your PR body; the promotion decision depends on it.
- **`ubuntu-latest` is the target. macOS is optional and you should probably not.** Linux is where this code has never run; macOS is where everything has always run. **If you add macOS, say why it earned its minutes.**
- **Hermeticity: this job is explicitly permitted to download a browser, and nothing else.** That is the one exception, it is the job's entire purpose, and it does **not** extend to the corpus suite — **story 6.1's corpus AC forbids network access and you do not touch it.** Two different suites, two different rules; keep them apart and say so in the workflow comments.

## Dev Notes

### Goal & Context

**Epic 5 shipped a browser verification surface that has only ever run on one machine.**

The five suites are good — real chromium, real `ProcessRunner`, real classification, a dedicated security suite. They also self-skip whenever no browser is present, which on every CI runner is always, because Playwright is an optional peer by binding spine decision and nothing downloads a browser. So the check goes green, and the greenness means five suites did not run.

That is the project's oldest hazard wearing new clothes. Epic 4's retro named it at the criterion level — *"every new way for a criterion to produce no attempts is a new way to reach green-for-nothing"* — and it has now recurred at the CI level. **The browser fixture's own header records the same guard failing once already**, when it resolved the environment too late and would have run browser tests on a browser-less machine instead of skipping: *"it passed here only because this machine has a browser, which is exactly how a guard stops guarding without anybody noticing."*

Story 6.1 made the skipping visible. **You make it stop.** And in doing so you get, for free, the first real execution of story 5.1's provisioning path and the first Linux run of the heaviest process tree this product spawns — the two gaps Epic 5's retro flagged as unclosable within that epic.

**Non-blocking is the right introduction and a bad permanent state.** Browser suites flake; a required check that cries wolf is worse than no check. So this lands amber, with a written promotion criterion, and the owner flips it on evidence. **A job nobody ever promotes is a job nobody ever reads** — which is why AC2 asks you for the criterion, not just the flag.
