**F3 — ⚠️ `setup.install` is declared in config but NEVER EXECUTED. CARRIED, NOT
FIXED — and it bounds this story's claim.**
`src/config/schema.ts:73-75` accepts `setup.install`; `src/pipeline/stages/setup.ts:18`
returns `createPlaceholderStage('setup', 'Epic 4 runs the configured install command')`,
and that placeholder is what is wired at `src/pipeline/stages/index.ts:151`. The
placeholder is visible at runtime in this fixture's own report:
`✓ ok  setup  0 ms  not implemented yet — Epic 4 runs the configured install command`.

**Why this matters here specifically.** The tempting write-up is "the Python fixture
verified with no install step, so installation is stack-neutral." That reasoning is
false. No project of **any** stack gets an install step today, so the install surface
is untested for everyone rather than neutral for everyone. Claiming FR-4 coverage
there would be the "green for the wrong reason" outcome this story exists to prevent.
Filling a placeholder pipeline stage is far outside a fixture story, so this is
reported with citations and left alone.

**F4 — Python's `http.server` performs a reverse-DNS lookup at bind time.**
Not a SpecWitness defect; recorded because the next non-Node fixture author will hit
it. `HTTPServer.server_bind` calls `socket.getfqdn(host)` to populate a field nothing
uses. **Measured: `socket.getfqdn('127.0.0.1')` took 35.0 seconds** on the authoring
machine, so the service never served inside the 30-second readiness budget and the run
failed with `service 'inventory' did not become ready within 30000ms`.

**I did not raise `ready.timeoutSec`.** That would have hidden the symptom and left a
DNS query — a network operation, which story 6.1 AC1 forbids — in the corpus, with a
duration set by the runner's resolver rather than by the program: precisely the
"fails on Tuesday" fixture the format is shaped against. The fixture overrides
`server_bind` to call `socketserver.TCPServer.server_bind` and skip the lookup.

**SpecWitness diagnosed this correctly**: exit 3, `infraError: infra`, never a product
FAIL, with a hint naming both remedies. A service that would not start says nothing
about whether the branch is mergeable, and the product said exactly that.
