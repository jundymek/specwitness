### Metric derivations — hand-computed, from records I wrote deliberately

Five scorecard records and five attributions, designed so that **each plausible way of being wrong changes a visible number**. Computed on paper before the code existed; never with the code under test.

| # | runId | outcome | durationMs | providerInv | flaky/retried | criteria f/nh/err | finding ids |
| --- | --- | --- | ---: | ---: | --- | --- | --- |
| 1 | r001 | PASS | 1000 | 0 | 0 / 0 | 0 / 0 / 0 | — |
| 2 | r002 | FAIL | 3000 | 0 | 1 / 2 | 2 / 0 / 0 | fail E6-01, E6-02 |
| 3 | r003 | NEEDS_HUMAN | 5000 | 1 | 0 / 1 | 0 / 1 / 0 | needs_human E6-03 |
| 4 | r004 | infraError `provider` | 7000 | 2 | 0 / 0 | 0 / 0 / 0 | — |
| 5 | r005 | FAIL | 9000 | 0 | 2 / 3 | 1 / 0 / 1 | fail E6-04, error E6-05 |

Attributions **in file order**: `(r002,E6-01) unique` → `(r002,E6-02) false-positive` → `(r003,E6-03) duplicate` → **`(r002,E6-01) false-positive` (supersedes the first)** → `(r005,E6-04) unique`. `E6-05` is deliberately left unjudged.

Winning map: E6-01 `false-positive`, E6-02 `false-positive`, E6-03 `duplicate`, E6-04 `unique`, E6-05 **unattributed**.

| metric | hand-computed | how |
| --- | --- | --- |
| **unique defects (north star)** | **1** | one winning `unique` — not 2, because E6-05 is unjudged and A1 was superseded |
| total findings | 5 | Σ(fail+needs_human+error) = 0+2+1+0+2, from the EXACT counts |
| attributed / unattributed | 4 / 1 | E6-05 is the one nobody judged |
| false-positive rate | 2 / 4 = 0.5 | denominated by attributed findings |
| NEEDS_HUMAN rate | 1 / 5 = 0.2 | r003 only |
| infra-error rate | 1 / 5 = 0.2 | r004 only — an infra-errored run DOES record (6.5 §2) |
| AI-free run share | 3 / 5 = 0.6 | r001, r002, r005 have `providerInvocations === 0` |
| flaky (retry-to-green) | 3 / 6 = 0.5 | Σ`flakyCriteria` ÷ Σ`retriedCriteria` |
| median duration | 5000 | sorted 1000·3000·**5000**·7000·9000, odd count |

**A gap I found in my own derivation, and fixed.** In this five-record set the mean and the median are *both 5000*, so it would **not** have caught a mean/median mix-up. A separate skewed even-count case was added — durations `1000, 3000, 5000, 91000` → **median 4000, mean 25000** — and guard 3 fails against it. This is the entire argument for computing expectations by hand: the set that looks thorough can be silently blind.

Edge cases asserted separately: empty (median `null`, every rate `null`), single record (that value), even count, all-skipped file, absent file, order-independence.

### Interpretations of story 6.5's record fields, with confidence

**No field required a guess.** Story 6.5's PR #71 §1 documents every field with *"meaning, and how 6.6 computes over it"*, exactly as that story's spec required, and its module header repeats it. Three places where a reading was still a choice, stated so nothing rests on silence:

1. **"Flaky rate" (AC2) = retry-to-green.** AC2 names the metric but not its denominator. 6.5 §1 defines the pair explicitly: *"Retry-to-green (SM-C3) = `flakyCriteria` ÷ `retriedCriteria`"*. I used that, summed across records. The alternative — flaky criteria over *all* criteria — would answer a different question ("how flaky is the suite") rather than SM-C3's ("when we retried, how often did it help"). **Confidence: high**, because 6.5 names the metric and the ADR-numbered success measure.
2. **The findings denominator comes from `criteria.{fail,needs_human,error}`, not from the id arrays.** 6.5 caps the arrays at 200 ids across a record and flags it, and states the counts *"stay exact regardless"*. Deriving the denominator from ids would silently shrink it for the runs with the most findings. **Confidence: high** — 6.5 §1 warns about exactly this in the `findingCriterionIdsTruncated` row.
3. **`skipped` criteria are not folded into anything.** Action item e4-D is open and 6.5 records `skipped` faithfully without editorialising. I count it and answer nothing. **Confidence: high** — my spec forbids answering it.

**One thing I deliberately did not use:** `stageDurationsMs`, `providerRoles`, `epic`, `adapted` and `contract` are all in the record and none is needed by AC2's seven metrics. Grouping by epic or splitting adapted from unadapted runs is real analysis, and my spec calls that speculation the MVP cannot afford.

### The codex review found six defects across three rounds, and one reversed a decision

**I read the report, not the status line** (e3-A). The harness classified both runs as `auto_review_findings`; the reports carried five findings, all valid, all fixed.

**Round 1 — two findings.**

**Round 2 — three findings, and the first reversed my D6.**

- **[P1] The round-1 fix opened a corruption vector.** Counting truncated-run attributions let *any* syntactically valid id count, so `attributed` and `uniqueDefects.count` could **exceed `findings.total`**. The `Math.max(0, …)` on `unattributed` hid the overflow rather than preventing it. **Resolved at the write end instead: `add` now refuses an unlisted criterion whether or not the record was truncated.** Both rounds flagged opposite symptoms of one design error, and refusing leaves the two halves nothing to disagree about. `attributed <= enumerated <= total` now holds structurally.
- **[P2] The terminal skip list named no fields.** ADR-008 §5 requires the line number *and the unknown fields*; the renderer printed only the reason word, discarding what the parser preserved.
