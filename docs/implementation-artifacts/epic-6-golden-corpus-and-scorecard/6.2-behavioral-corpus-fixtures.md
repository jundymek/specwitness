**These five fixtures are the product's argument.**

Everything shipped in five epics is machinery. The claim the machinery exists to support is the brief's §7: *there is a class of defect that survives coding-agent tests, Codex review and supervisor review, and only appears when the assembled epic runs.* Nothing in the repository demonstrates that claim today. The discipline that makes this work is uncomfortable and it is the whole job: **when a fixture disagrees with the product, you must decide which is wrong before you touch either.** The easy resolution — adjust the expectation until it matches — turns five proofs into five tautologies, and it will feel like progress every single time.

### Failure modes (what "wrong" looks like here)

- **Bending `expected.json` to match observed output.** The one failure that makes the whole epic worthless, and it will present itself as finishing the task.
- **A "defect" a story-level gate would have caught** — a type error, a lint failure, a red unit test. It proves nothing about epic-level verification.
- **Fixture 10 with a module whose own tests fail.** Then it is not the cross-story class at all.
- **A fixture failing for the wrong reason** — a service that did not start, a port collision, a missing binary — while its `expected.json` claims it proves an API-contract mismatch. **This is the most likely real defect in your story.**
- **An all-correct fixture that passes because nothing was adjudicated.** Green for nothing, one level up.
- **Renumbering fixtures**, breaking four merged ACs across two epics that name them by number.
- **Fixing merged pipeline code** to make your fixture green.
- **A fixture that leaks a process or mutates the checked-in tree.**
- **Reporting CI as "pending owner".** It runs now.

### Security

- **⚠️ YOUR STORY ADDS EXECUTABLE COMMANDS TO THE REPOSITORY.** A fixture's `.specwitness/` config is a declared-command surface (AD-3), and five fixtures means five configs whose commands run in CI on every PR, on two platforms, forever. Treat every one as a security-relevant change:
  - keep each command trivially inspectable, local, and obviously harmless;
  - **no command reaches the network**, downloads anything, or touches anything outside its own temp workspace;
  - no fixture app contains a real credential, token, or anything shaped like one — **including in a comment showing what would be redacted.**
- **Never mint a `DeclaredCommand`** outside the config boundary (`tests/unit/config/boundary-scan.test.ts` covers you).
- **Never read, copy or persist `~/.claude/`, `~/.codex/` or any credential store** (NFR-1, AD-4, Q59).
- **Assert a secret is ABSENT, never that `[REDACTED]` is present** (Epic 3 retro §7).
- **This story makes zero provider calls**, which is worth stating.
- **Your security sign-off may be the last gate before merge** (Stage 4). Sign off from the actual report. **And note that every fixture edit re-stales it** — plan the sign-off for the end.
