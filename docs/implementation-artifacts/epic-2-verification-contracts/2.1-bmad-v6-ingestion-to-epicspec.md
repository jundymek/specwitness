## Story

As a BMAD user,
I want SpecWitness to read my epic, stories, and acceptance criteria into a normalized EpicSpec,
so that contract generation is isolated from planning-artifact formats (FR-5, FR-6).

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** configurable artifact roots (defaults `docs/planning-artifacts`; first-client override `docs/planning-artifacts` + `docs/implementation-artifacts`)
   **When** I ingest `epic-7` (input accepted as `7`, `epic-7`, or `epic-07`)
   **Then** the EpicSpec contains the epic id/title/goal and every story with its numbered acceptance criteria verbatim, with source file references.
2. **Given** per-story markdown files (`## Story`, `## Acceptance Criteria` numbered lists) and/or the epics file
   **When** either layout variant is present
   **Then** ingestion succeeds from both (fixtures for both variants).
3. **Given** an epic that cannot be found or parsed
   **When** ingestion runs
   **Then** an IngestError names what was searched and where (exit 3), and no empty EpicSpec is produced.
4. **Given** the EpicSpec type
   **When** downstream code is compiled
   **Then** no BMAD-specific types are imported outside `ingest/` (AD-1 boundary test).

Clarifications (detail only, no weakening):

- **AC1 epic id normalization is NOT yours to write.** `normalizeEpicId` already exists in `src/domain/ids.ts` (merged, story 1.2) and accepts `7` / `07` / `epic-7` / `EPIC-07` → canonical `epic-7`, throwing `UsageError` on anything else including `0`, negatives and unsafe integers. Do not normalize case, punctuation, or internal whitespace, and do not reflow. The contract author downstream reads these as the source of truth; a silently reworded criterion is the exact "correlated misunderstanding" failure this product exists to catch.

- **AC3 error content:** the `IngestError` message must name the canonical epic id, every path searched (both roots, both layout patterns, expanded), and what was found instead (e.g. "epics.md exists but contains no `## Epic 7`"). - **AD-5.** `EpicSpec` carries `schemaVersion` from the registry. It is an in-memory model in V0 (nothing persists an EpicSpec to disk), but the version is part of the contract from day one.
- **Conventions.** Kebab-case filenames; PascalCase types; camelCase fields; ISO-8601 UTC for any timestamp; `ERROR:`/`HINT:` rendering is the CLI's job — you throw, you never print and you never set an exit code (`tests/unit/exit-location.test.ts` enforces this).

### Failure modes to consider

- **Epic 10 vs epic 1 prefix collision.** `## Epic 1:` must not match when epic 10 was asked for, and `epic-1-slug/` must not match a request for `epic-11`. Anchor on the full number.
- **CRLF line endings and a BOM** in a checked-out artifact — normalize on read (strip a leading `﻿`, split on `\r?\n`) or your heading matcher silently finds nothing.
- **The two layouts differ in criterion syntax and the parser must handle each.** `<planningArtifacts>/epics.md` uses `**Acceptance Criteria:**` followed by unmarked `**Given**/**When**/**Then**` paragraph blocks — no list markers at all, one block = one criterion. Per-story files under `<implementationArtifacts>/` use `## Acceptance Criteria` with numbered `1.` items. Accept `- ` bullets in either. Both specimens are in this repository; read one of each before writing the parser.
- **A `## Acceptance Criteria` section followed immediately by another `##` heading** (empty section) — that is the AC3 zero-criteria error, not an empty array.
- **Symlinked or unreadable artifact directories** — an `EACCES` must surface as an `IngestError` naming the path, never as an unclassified crash (which would still exit 3, but with "this is a SpecWitness bug" text that misdirects the user).
- **A trailing `epic-7-something/` directory that is empty** — searched, found nothing, must be named in the error.

### Security

- Ingestion **reads files and nothing else**: no subprocess, no network, no environment reads, no writes. Nothing here may execute a project-declared command (AD-3), and nothing here may read outside the two configured roots under the given project root.
- Do not follow `..` out of the project root when expanding a configured root. A configured root that escapes the project root is a **`ConfigError`**, not an `IngestError`: the fault is in `.specwitness/config.yaml`, not in the planning artifacts. Both map to exit 3, but `INFRA_ERROR_CLASSIFICATIONS` in `src/domain/run-outcome.ts` carries `config` and `ingest` as distinct values that surface in run metadata and doctor — misclassifying sends the user to re-check the wrong thing. Name the resolved path either way.
- NFR-1 (no credential-store reads) is trivially satisfied here — do not touch the home directory at all.

### Debug Log References

- **The `Clarifications` trap (the one real parsing hazard).** Reading the real
  specimens first paid for itself immediately. Every per-story file in this
  repository follows its numbered criteria with a `Clarifications (detail only,
  no weakening):` paragraph and its own `- ` bullet list. The spec says "Accept
  `- ` bullets in either" layout, and a parser that took that literally would
  ingest those editorial notes as acceptance criteria — story 1.4 would report
  8 criteria instead of 3, and the contract author downstream would draft
  verification criteria for editorial asides. Resolved by taking the FIRST
  CONTIGUOUS LIST BLOCK of the section, which also skips the ``From
  `docs/planning-artifacts/epics.md` (authoritative …):`` preamble for free.
  Pinned by `tests/unit/ingest/story-files.test.ts` and again against the real
  artifacts in `real-artifacts.test.ts`.

- **Strategy selection cannot look at the first line.** The obvious rule ("is
  the first line a list item? then parse a list") takes the paragraph path on
  every real story file, because the first line is the preamble prose — and
  would then emit that preamble as criterion 1. The strategy is chosen by
  whether the section contains ANY list item anywhere.

- **`---` terminates an epic section.** Every epic in `epics.md` is closed by a
  thematic break before the next `## Epic` (lines 283, 441, 591, 737, 847, 949).
  Without treating `---` as a terminator, epic 7's section runs to end of file
  and the last story of every other epic absorbs the rule line.

- **A `*/` inside a doc comment broke the build once.** The markdown module's
  header originally contained the literal `**Given**/**When**/` while describing
  the epics-file criterion syntax; the `**/` closed the block comment and oxc
  reported a parse error. Reworded rather than escaped.

- **The containment test was wrong before the code was.**
  `../epics-only/docs/planning-artifacts` resolves back INSIDE the project root,
  so refusing it would have been security theatre that breaks a legitimate
  config. The test now pins the property that matters — where a root LANDS —
  and a separate case covers a genuine escape. While there, closed the symlink
  variant of the same hole: `resolve` is purely lexical, so containment is
  checked again against the real path when the root exists.

- **Codex review found three real defects; all three are fixed and pinned by
  regressions in `tests/unit/ingest/codex-findings.test.ts`.**
  1. *(P1)* `extractCriteria` chose list mode if the section contained ANY list
     item anywhere. A paragraph-style criteria section followed by a trailing
     bullet list therefore had its real Given/When/Then criteria silently
     DISCARDED and replaced by those bullets — the same corruption I had guarded
     against in the other direction, reached from the opposite side. The format
     is now chosen by WHERE the first list sits among the section's blocks: at
     block 0 it is the criteria; at block 1 it is the criteria when block 0 is a
     lead-in (a paragraph ending in `:`); any later it is trailing matter and the
     paragraphs before it — minus a lead-in that introduces it — are the criteria.
  2. *(P2)* An artifact root of `.` made `relative(projectRoot, projectRoot)`
     return `''`, so interpolation produced `/epics.md`: read correctly, but
     absolute-looking, unportable, and rejected by `sourceRefSchema`. All
     repo-relative paths are now built by `repoPath()`, which drops empty and
     `.` segments.
  3. *(P2)* Containment was enforced on the artifact ROOT only, so a symlinked
     `epics.md` or epic directory inside a legitimate root still read outside the
     repository. Containment is now per-entry: every file and directory is
     resolved and checked before it is opened. Classified `IngestError`, not
     `ConfigError` — the config named a legitimate root; the escaping symlink is
     in the artifact tree.

- **A second Codex round found two more real defects; both fixed, both
  reproduced red first.**
  4. A `### Story` heading that could not be parsed — a malformed number, or a
