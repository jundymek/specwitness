## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** the adapter
   **When** it invokes claude
   **Then** it uses the probed non-interactive form (baseline `-p --output-format json`), runs via ProcessRunner with timeout, and parses only the structured envelope.
2. **Given** capability probing
   **When** the local claude lacks required capabilities or is absent
   **Then** a capability error is reported and surfaced through doctor — no hardcoded assumption beyond the tested minimum.
3. **Given** subscription mode
   **When** the subprocess environment is constructed
   **Then** `ANTHROPIC_API_KEY` (and configured equivalents) are withheld from the child env; the parent env is never mutated; a warning names the variable when present.
4. **Given** the entire adapter codebase
   **When** reviewed/tested
   **Then** no path reads `~/.claude/` or any credential store (NFR-1; static check + review checklist).

### Architecture compliance

- **AD-2.** Translate the envelope to a CLI invocation and return raw text. Nothing else.

### Failure modes to consider

- **A `claude` on PATH that is not Claude Code** (a shell alias, a homonym script) — the version probe must not accept arbitrary output as proof of capability.
- **The JSON envelope shape changing between CLI versions** — parse defensively, and produce a capability/provider error naming what was expected, never a `TypeError` from a property access on `undefined`.
- **A payload that is valid JSON but not the fenced text you expected** — return it raw and let the gate reject it with a recorded attempt. Never "repair" a payload.
- **A prompt containing shell metacharacters** — argv arrays make this a non-issue, and a test should prove it rather than a comment claiming it.
- **A very large prompt** hitting an argv length limit — decide (stdin? a temp file inside the run directory?) and document; do not discover it in Epic 7 against a real epic.
- **`claude` writing progress to stderr** — do not treat non-empty stderr as failure; use the exit code and the envelope.
- **A hung CLI waiting for a TTY** — this is the exact failure `-p` prevents; the timeout plus `input: ''` is the backstop, and the hanging-shim test is the proof.
- **`ANTHROPIC_API_KEY` set but empty** — decide whether an empty value warrants the warning (recommendation: treat presence-of-the-name as presence, and say so).

### Security

- **NFR-1, absolutely:** no path reads `~/.claude/`, `~/.codex/`, `CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `.netrc`, or any credential file. Authentication is entirely the CLI's own business. Enforced by the AST guard; verify it fires on your file.
- **No shell.** Fixed binary name, argv array, no `shell: true`, no `sh -c`, no string interpolation of anything into a command.
- **The parent environment is never mutated.** Withhold by construction; assert non-mutation in a test.
- **No credentials are ever logged, persisted, or included in an attempt record.** Attempt payloads are model output; if a prompt or response were ever to carry a secret, redaction is Epic 4's AD-10 concern at evidence capture — do not build a redactor here, but do not print the child environment either.

### Completion Notes List

- **All six tasks complete.** 35 unit tests, 17 integration tests (16 run, 1
  skipped by design), plus 19 tests for the shared helper and 12 for the shim
  fixture itself.
- **`src/providers/text.ts` shipped first, in its own commit**, ahead of the
  adapter, because story 2.5 was blocked on it. Its owner was assigned in this

  strippers; rambo read it, accepted it, and imports rather than vendors it.
- **Strict-by-design fence stripping.** An unterminated fence, or one opening
  after prose, is returned byte-identical. A truncated response is a real
  failure mode, and inventing where the payload ends would hand the gate a
  silently corrupted body instead of an honest rejected attempt.
- **Deviation from the spec's AC3 wording, deliberate and safety-increasing:
  withholding is UNCONDITIONAL, not conditional on `subscription`.** Verified
  independently after rambo raised it: `src/config/schema.ts` types `mode` as
  `nonEmptyString` (no enum), the only modes any artifact defines are
  `subscription` and `chatgpt`, and nothing anywhere defines a mode that opts
  INTO API-key billing. A conditional withhold would therefore make silent
  billing reachable by a typo that validation cannot catch (`mode:
  subscribtion`). Unconditional withholding is a strict **superset** of AC3, not
  a weakening. An unrecognized mode withholds anyway and warns; a set-but-empty
  variable counts as present. Adding an opt-in billing mode later is a
  config-schema change plus an ADR, never a condition in an adapter.
- **The stdin fallback was nearly an unprobed assumption.** `claude --help`
  documents no stdin path at all — no `-` sentinel like codex has — so the
  planned 64 KiB fallback rested on belief until measured. It works; and because
  stdin is *appended* to an argv prompt rather than replacing it, the two paths
  are now mutually exclusive by construction, with tests pinning both shapes.
  The failure mode is silent: a duplicated prompt still produces plausible
  output, so nothing downstream would have caught it.
- **The 64 KiB threshold is measured, and the binding platform is the untested
  one.** macOS here allows a ~1017 KiB argv element, but Linux caps a single
  argument at `MAX_ARG_STRLEN` = 128 KiB independently of its larger `ARG_MAX`.
  The permissive host is the one that hides the bug. Agreed identically with
  story 2.5 so a reviewer comparing the adapters sees one decision, not two.
  **The Linux figure is documented, not verified here** — no Linux host in this
  worktree.
- **Capability is proved by behaviour, never by the version string**, which an
  alias or homonym `claude` on PATH can print freely. The version is passed
  through verbatim because story 2.2's `providerCliVersion` provenance field is
  filled from it; parsing it into a feature matrix is forbidden by AC2 and would
  be the wrong shape for provenance anyway.
- **Nothing on the probe path throws.** A missing CLI is a value with an
  actionable reason, so doctor can warn while leaving its exit code at 0 (UJ-4).
  `not-found` means only "not on PATH" — story 2.3 made a bad working directory
  `spawn-failed` so this message cannot misdiagnose a wrong cwd as a missing

**Two defects found by Codex review after the rebase, both fixed, both verified
red first. They are recorded here because each was a real design error rather
than a typo:**

1. **The capability probe conflated flag support with authenticated
   availability.** It runs a real invocation, so it also fails when the operator
   is logged out, rate limited or out of quota — and those were being reported as
   "the CLI is too old, or is not Claude Code". Worse, `generate()` refused on
   that verdict, so the operator never reached the invocation path that would
   have shown the CLI's own message. A logged-out user was told to reinstall a
   working binary. Now only a genuine *argument* rejection counts against
   capability; anything else means the flags were accepted and readiness is
   `probeClaudeAuth`'s question. The stderr heuristic is deliberately biased
   toward "the flags were fine": a false negative merely lets `generate()` report
   the real complaint, whereas a false positive misdiagnoses a healthy install.

2. **`billingEnvVars` was unreachable in production.** `createProvider` builds
   the adapter with no options and the provider config schema is a `strictObject`
   of `{adapter, mode}`, so the option was reachable only from tests — while the
   comment implied projects could configure equivalents. The default is therefore
   the only list that ever applies, and it now includes `ANTHROPIC_AUTH_TOKEN`
   alongside `ANTHROPIC_API_KEY`; both authenticate a billed Anthropic account,
   which is what AD-4's "provider equivalents" means. The comment now states
   plainly that the option is an injection seam, not a config surface.
   **Left for the epic:** giving projects a way to declare their own billing
   variables is a config-schema change plus an ADR, not an adapter change.

3. **The capability probe accepted exit code 0 as proof of JSON support.** A
   homonym `claude` that swallows the flags and prints prose successfully would
   have been reported as capable, so doctor would declare a healthy install while
   every generation failed later in envelope parsing — the exact failure mode
   this spec's "Failure modes to consider" names first. The probe now requires
   output that parses as a JSON **object**. Only the form is checked, never the
   fields: capability means the CLI honours the flag, whereas a drifted envelope
   shape belongs to a real invocation where the error can name the missing field.

4. **The probe ran in `process.cwd()` while generation ran in the configured
   cwd**, so it answered for a different directory than the work uses — and 2.3
   classifies a bad working directory as `spawn-failed`, so a provider could be
   approved from the ambient directory then fail in the configured one. The cache
   is now keyed by cwd as well as runner, since two directories can legitimately
   disagree.

5. **The timeout hint advised raising a timeout that cannot be raised.** The
   provider config is `{adapter, mode}` and `createProvider` passes no options, so
   the primary remedy was one no operator could take — worse than no hint under
   the house `ERROR:`/`HINT:` contract. It now offers only reachable actions.

6. **Caller-supplied billing variables replaced the defaults rather than extending them** (P1). Passing one custom name silently un-withheld `ANTHROPIC_API_KEY` and `ANTHROPIC_AUTH_TOKEN` from every probe and generation — an operator acting *more* cautiously would have produced the exposure this adapter exists to prevent. The list is now a union of the defaults with anything the caller adds; withholding fewer than the defaults is no longer expressible.

**A flake I reported rather than fixed.** One full-suite run showed
`tests/unit/exit-location.test.ts` → "reports no offender outside the allowed
module" failing; not reproducible in isolation (6 runs) nor across 22 subsequent
full runs. This is the defect **story 2.8** (`hermetic-dependency-rules-test`,
written by the epic supervisor) already owns, and its documented mechanism fits
exactly: `dependency-rules.test.ts` writes fixed-name scratch modules into the
real `src/` tree, while Codex's post-push auto-review runs `pnpm test` in this
worktree concurrently with the agent's own runs. PRs #9 and #11 reported the same
thing; this is a third independent sighting. Nothing in this story's diff writes
under `src/` at test time — its shims live only under `mkdtemp`.

**The two adapters withhold different variable lists, deliberately.** A reviewer comparing 2.4 and 2.5 will see `ANTHROPIC_API_KEY` + `ANTHROPIC_AUTH_TOKEN` here and only `OPENAI_API_KEY` there. That is the same rule producing different answers, because the variables differ in kind: `ANTHROPIC_AUTH_TOKEN` is a bearer token for the **billed API**, and withholding it costs a subscribed user nothing (subscription auth lives in the credential store, which neither adapter touches). `CODEX_ACCESS_TOKEN`, the apparent mirror, is the **ChatGPT subscription credential itself** — withholding it would prevent no charge while breaking a legitimately signed-in user. Story 2.5 checked and declined to mirror this change for exactly that reason; mirroring it would have been cargo-culting.

**The residual risk on this side, stated rather than left to be found:** anyone routing Claude Code through a gateway that authenticates via `ANTHROPIC_AUTH_TOKEN` will be broken by unconditional withholding. That is accepted, because no artifact defines a mode that opts into API-credential use — so the configuration is outside V0's supported set — and because after the capability-probe fix such a user now receives the CLI's own auth message plus a warning naming the withheld variable, which is a diagnosable failure rather than a silent one. Supporting gateway routing would be a config-schema change plus an ADR, like the opt-in billing mode.
