## Story

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** roles `contract-author`, `plan-author`, `explainer` in config
   **When** a role is invoked
   **Then** the assigned provider is used; any role can map to any single configured provider; unassigned optional roles degrade gracefully.
2. **Given** a provider response
   **When** it fails schema validation
   **Then** a retry with the validation errors appended is attempted at most N times (default 2), each attempt recorded (count + rejected payload stored), then a ProviderError (exit-3 class) is raised — never a partial artifact.
3. **Given** FakeAgentProvider
   **When** the domain/application test suite runs
   **Then** zero real subprocesses are spawned and all contract-generation logic is covered through the fake.

Clarifications (detail only, no weakening):

- **AC1 role keys stay kebab-case.** `AI_ROLES = ['contract-author', 'plan-author', 'explainer']` and the `ai.roles` schema already exist in `src/config/schema.ts` (merged, story 1.3), and `resolveRoleProvider(config, role)` already exists in `src/config/types.ts` returning `{name, adapter, mode} | undefined`. The kebab-case-vs-camelCase divergence was flagged in Epic 1 (retrospective §4, action item A2) with the supervisor recommending **keep**; treat kebab-case as settled unless the owner says otherwise in your inbox. **Do not rename the keys**, and do not re-implement role resolution — call `resolveRoleProvider`.
- **AC1 "degrade gracefully":** `resolveRoleProvider` returning `undefined` is a normal, non-throwing outcome that the *caller* decides about. A missing `explainer` must never break contract generation (that is UJ-4's edge case). Your layer surfaces the absence as data; it does not throw and does not substitute a default provider.
- **AC2 the gate and the retry loop are implemented exactly ONCE**, in `src/providers/invoke.ts` (AD-2 names this file by path). Adapters never validate, never retry, never see the schema. The loop: send prompt → adapter returns raw text → parse + zod-validate → on failure, append the *validation errors* to the next prompt and retry → after N failures (**default 2 retries, i.e. at most 3 attempts total** — say which reading you implemented in your module header and make the config field unambiguous) throw `ProviderError`. Every attempt is recorded with its raw/rejected payload.
- **AC2 "never a partial artifact":** `parsed` exists on the response only when the gate validated it. Model this in the type system, not by convention — a discriminated union (`{ok: true, parsed, ...} | {ok: false, ...}`) or equivalent, so a caller cannot read `parsed` off a failed response without a compile error. AD-2 states "parsed exists only after the shared gate"; make that a type property.
- **AC2 the rejected payload is stored but is NOT authoritative.** It is diagnostic text. It must never be parsed for partial data, never merged with a later attempt, and never persisted anywhere a downstream reader might mistake it for content.
- **AC3 FakeAgentProvider placement — decide explicitly and record it.** Recommendation, and the reason: build a **runtime-selectable `src/providers/fake.ts`** adapter selected by config `adapter: fake`, returning deterministic canned responses loaded from a fixture directory. Epic 6's hermetic corpus e2e drives the real `specwitness` binary with no real providers, which a `tests/`-only double cannot serve. Pure unit-test doubles (a two-line inline object implementing `AgentProvider`) stay in `tests/fakes/`, per Epic 1's decision that fakes live in the tests tree (retrospective §5.2). **If you choose differently, say so in your PR body and message arnold, rambo, chuck and dolph** — all four reference this location.
  - Selecting `adapter: fake` requires extending the `providerSchema` enum in `src/config/schema.ts` (currently `['claude-code-cli', 'codex-cli']`). That is a one-value additive change to a file story 1.3 owns and no one else touches this wave; make it, and call it out in your PR body.
- **AC3 "zero real subprocesses":** add a test-level guard, not just a convention. A unit test that fails if the domain/application suite would spawn — e.g. injecting a `ProcessRunner` that throws on any call and asserting the fake path never reaches it.
- **The process seam is yours to create, minimally** (see Dev Notes → Project Structure Notes for the full decision). 2.4 and 2.5 need to spawn a binary with a timeout, captured output and a constructed environment; Epic 3 story 3.2 owns the full `ProcessRunner` with process groups and manifest discipline. You ship the **minimal port + execa implementation**; 3.2 extends it.

### Failure modes to consider

- **A provider that returns valid JSON of the wrong shape** — that is a gate failure, not a parse crash; both paths must record an attempt.
- **A provider that returns JSON wrapped in prose or a markdown fence.** claude's `--output-format json` returns an envelope whose payload may itself be fenced text. Decide where fence-stripping lives — **the adapter** (it is CLI-output translation) — and say so, so 2.4 and 2.5 both do it and your gate stays schema-pure.
- **An empty response, or a response on stderr only** — must produce a recorded attempt with the empty payload, not an unclassified crash.
- **A timeout mid-generation** — an `InfraError` or a `ProviderError`? Decide and document: a timeout is the *provider* failing to deliver, so `ProviderError` (exit 3 either way, but the classification is visible in run metadata and in doctor).
- **Retry amplification.** Each retry is a fresh agent session and costs real subscription quota. Retries are bounded, never nested (do not retry inside the adapter as well as inside the gate), and the count is recorded so the cost is visible.
- **`process.env` mutation by a library.** Assert non-mutation after a call rather than trusting execa's contract.
- **A zero or negative configured retry count** — clamp and document, or reject; either way do not loop forever.

### Security

- **NFR-1 is a tested property here.** No path under `src/providers/**` may read `~/.claude/`, `~/.codex/`, or any credential store. Extend the merged AST guard to cover your directory and verify it fires. Its honest limit is unchanged: a fully computed `process.env[variable]` defeats any static scan, and code review is the backstop.
- **Provider binaries are NOT `DeclaredCommand`s, and that is deliberate.** `claude` and `codex` are SpecWitness's own trusted tools, invoked by fixed name with a fixed argument array — exactly like `git` in `src/cli/doctor/effects.ts`. `DeclaredCommand` exists to constrain *project-declared* shell strings (AD-3), and it is minted only inside `src/config/`. Do not try to mint one, do not import the brand, and do not add an escape hatch to `src/config/` — `tests/unit/config/boundary-scan.test.ts` will reject deep imports and brand casts mechanically. State this reasoning in your module header so no later story re-litigates it.
- **No shell, anywhere.** No `shell: true`, no string command, no `sh -c`. Argument arrays only. This is what makes it impossible for provider output to become an executable command.
- **The parent environment is never mutated** — construct the child env, pass it, done.
