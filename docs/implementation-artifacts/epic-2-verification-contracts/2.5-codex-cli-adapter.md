1. **Given** the adapter

2. **Given** OPENAI_API_KEY present in chatgpt mode

Clarifications (detail only, no weakening):

- **AD-4's hardcodable minimum for codex is `exec --output-schema` — two things, not a flag list.** The following were all verified present on this machine 2026-08-31 (**codex-cli 0.144.4**, matching addendum §B) and are what you may probe *for*, never what you may assume: `-o/--output-last-message <FILE>`, `-C/--cd <dir>`, `--json`, `-s/--sandbox <mode>`, `--skip-git-repo-check`, and the `codex doctor` subcommand. Probing is per session and cached; a capability you need but cannot confirm produces a capability error, not a hopeful invocation (AD-4, ADR-001 concern 1: these CLIs evolve fast).
- **AC1 `--output-schema` is a real advantage — use it, and do not let it replace the shared gate.** Codex can constrain its final response to a JSON Schema, which makes malformed output rarer; it does **not** make it impossible, and AD-2 requires that *every* provider response pass `providers/invoke.ts`'s zod gate before becoming state. Generating the schema file is your job; validating the response is not.
  - Convert the request's zod schema to JSON Schema with **zod 4's built-in `z.toJSONSchema()`** — zod 4.5 is already a dependency and ships this; do **not** add `zod-to-json-schema` or any other package (the Stack table is pinned; a new runtime dependency is an ADR, not a story decision). Verify the function exists in the installed version before relying on it, and say what you found.
  - Write the generated schema to a **temp file** you create and delete, never into the user's project tree. Prefer the OS temp dir (nothing in this story writes to `.specwitness/`; `RunStore` is the sole writer under `runs/` per AD-8, and you are not in a run).
- **AC1 `--output-last-message <FILE>` is how you capture the answer deterministically.** Read that file rather than scraping stdout: stdout carries progress and event text, and parsing it would be exactly the fragile coupling AD-4 warns about. Return the file's content as **raw text**.
- **AC1 `-C <dir>`:** pass the project root (or the directory the caller specifies) explicitly rather than relying on inherited cwd. If the target directory is not a git repository, `--skip-git-repo-check` is the probed flag that makes it work — probe it, do not assume it.
- **AC1 the adapter returns raw text only.** No zod call, no retry, no attempt recording, no domain object construction — all of that is `providers/invoke.ts` (2.3), implemented once, per AD-2. If you find yourself writing a zod validation in this file, stop.
- **AC2 withholding, not unsetting.** Build the child environment by **omitting** `OPENAI_API_KEY` (plus any configured equivalents) from an otherwise-inherited environment. Never `delete process.env.X`, never assign to `process.env`. Add a test asserting `process.env` still holds the variable after the call. `chatgpt` is the mode that withholds (config `ai.providers.<name>.mode`, already validated by story 1.3). For an unrecognized mode, mirror 2.4's decision — **withhold anyway and warn** — and document it; failing safe on billing is cheaper than an unexpected charge. Agree the wording with arnold so both adapters warn identically.
- **AC2 the warning names the variable** (FR-15): e.g. `⚠ OPENAI_API_KEY present in environment — withheld from the codex subprocess (mode: chatgpt)`.
- **AC3 "no hardcoded dependency on any specific provider"** is a property of the *system*, proven from your side: a config declaring only a codex provider, with all three roles pointing at it, completes an invocation through 2.3's gate against your mocked binary. Arnold asserts the mirror image. Neither of you may reference the other's adapter by name outside config-driven resolution.
- **Capability probing and NFR-1 apply identically to 2.4.** Probe binary presence, version and the `exec` subcommand per session and cache it; expose a typed capability result for 2.7's doctor check rather than throwing from inside an invocation; never read `~/.codex/`, `CODEX_HOME`, or any credential store. 2.3 extends the merged NFR-1 AST guard to `src/providers/**`; **verify it actually fires on your file** (plant a `~/.codex/auth.json` literal, watch it go red, revert).
- **`codex doctor` is the auth-readiness probe** (Q58) — the CLI's own public surface, never filesystem inspection. Expose it (or tell dolph plainly that it belongs on the doctor side) and coordinate during intent-sync; 2.7 merges after you and must not invent a second probe.

## Dev Notes

### Goal & Context

Codex is the model-diversity half of ADR-001: a Codex-authored verification contract for Claude-authored code is a genuinely independent reading of the same spec, which is the whole premise of catching correlated misunderstanding. The addendum's config sketch assigns `contract-author` to codex for exactly that reason. Your adapter is a **thin translation layer**: envelope in, argv out, raw text back. Codex's `--output-schema` makes it a better-behaved provider than claude; it does not make it an authority.

### Exact scope

- `src/providers/codex-cli.ts` (NEW) + at most one small adapter-local helper file
- `tests/unit/providers/codex-cli.test.ts`, `tests/integration/providers/codex-cli.test.ts`, PATH-shim fixtures under `tests/fixtures/bin/`
- `docs/implementation-artifacts/sprint-status.yaml` — your row only

### Out of scope (do NOT build)

- **Schema validation, retries, attempt recording, `ProviderError` raising on invalid content** — all `src/providers/invoke.ts` (2.3, merged before you start). `--output-schema` constrains the model; it does not replace the gate, and a second validation implementation here is the defect AD-2 exists to prevent.
- **The claude adapter** — 2.4 (arnold). Do not touch `src/providers/claude-code-cli.ts`.
- **Doctor checks and their rendering** — 2.7 (dolph). You expose the capability result and the `codex doctor` probe; dolph registers the check.
- **The contract command, prompts, prompt engineering** — 2.6 (chuck) decides what to ask.
- **`ProcessRunner` changes.** If you need something the merged port lacks, **message pamela and the supervisor rather than editing it** — arnold builds on the same file and Epic 3 story 3.2 extends it.
- **`--json` JSONL event-stream parsing.** `--output-last-message` gives you the final answer deterministically; consuming the event stream is scope you do not need and a coupling you do not want.
- **Sandbox-mode policy (`-s/--sandbox`).** Do not set a sandbox mode without an explicit decision; if you believe one is needed, raise it rather than choosing silently — it changes what the delegated agent may do on the user's machine.
- **Reading, copying, or persisting anything under `~/.codex/`** — forbidden absolutely (NFR-1).
- **Any direct OpenAI API call, SDK, or `fetch`** — ADR-001; V0 has no API path at all.

### Architecture compliance

- **AD-1.** `src/providers/**` is an adapter: it may import `src/domain/**`, `src/schemas/**` and npm packages — and **not** `cli/`, `config/`, `infra/`, `surfaces/`, or the application layer. Configuration arrives as arguments, resolved by the caller. (The `adapters-core-only` rule's `$1` group substitution lets `src/providers/*` import its own siblings — pinned by `tests/unit/dependency-rules.test.ts`; do not "fix" that rule under review pressure, a Codex review got it wrong once already.)
- **AD-2.** Translate the envelope to a CLI invocation and return raw text. Nothing else.
- **AD-3 stays intact.** Fixed binary name + argv array; no shell; nothing from config or provider output is ever interpolated into a command line. `codex` is SpecWitness's own trusted tool (like `git`), **not** a `DeclaredCommand` — do not import the brand or try to mint one; `tests/unit/config/boundary-scan.test.ts` rejects both mechanically.
- **AD-4.** Probe, cache per session, withhold billing-risk variables, never mutate the parent env, never read credential stores, probe auth only via the CLI's public surface (`codex doctor`).
- **AD-8 note.** You are not in a run, so you write nothing under `.specwitness/`. The generated schema file and the last-message file go in the OS temp dir and are cleaned up.
- **Conventions.** `durationMs` integer ms; ISO-8601 UTC; env read only in `cli/`/`infra/` — keep your `process.env` surface to the specific billing variable FR-15 requires you to detect.

### Failure modes to consider

- **A `codex` on PATH that is not the Codex CLI** — the version/`exec` probe must not accept arbitrary output as proof of capability.
- **`--output-schema` rejecting a schema zod produced** (unsupported JSON Schema draft features, `$ref`s, unions). This is the most likely real failure in this story: test the conversion against your actual contract-draft schema shape and, if a construct is unsupported, simplify the schema you *send* rather than weakening the schema you *validate against* — the gate stays strict.
- **The last-message file never being written** (a failed run, a killed process) — a provider-classified failure naming the missing file, never a `TypeError` or a silent empty success.
- **Temp-file leakage** — clean up in `finally`; two concurrent invocations must not collide on a filename.
- **`-C <dir>` pointing at a non-git directory** — `--skip-git-repo-check` exists for this; probe it rather than assuming it, and produce a clear capability message if it is unavailable.
- **A prompt containing shell metacharacters** — argv arrays make this a non-issue; prove it with a test rather than a comment.
- **A very large prompt** hitting an argv length limit — decide (stdin? a temp file?) and document it now rather than discovering it in Epic 7.
- **`codex` writing progress to stdout/stderr** — you read the last-message file; do not treat non-empty stderr as failure.
- **`OPENAI_API_KEY` set but empty** — mirror arnold's decision (recommendation: presence-of-name counts) so the two adapters do not disagree.

### Security

- **NFR-1, absolutely:** no path reads `~/.codex/`, `~/.claude/`, `CODEX_HOME`, `CLAUDE_CONFIG_DIR`, `.netrc`, or any credential file. ChatGPT OAuth stays entirely the Codex CLI's business. Enforced by the AST guard; verify it fires on your file.
- **No shell.** Fixed binary name, argv array, no `shell: true`, no `sh -c`, no interpolation.
- **The parent environment is never mutated.** Withhold by construction; assert non-mutation in a test.
- **Temp files carry a schema and a model answer, not secrets** — still, create them with default-private permissions in the OS temp dir and delete them, and never log the child environment.
- Write a substantive `set-security-status.sh` note (`SECURITY_GATE=1` is on): no shell, no credential reads, env withheld by construction, parent env unmutated, temp files cleaned, no DeclaredCommand minting.
