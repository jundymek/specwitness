## Story

As an epic owner,
I want to generate a draft contract, review/edit it, and explicitly freeze it before the cohort starts,
so that the definition of done is captured independent of future implementation (FR-7, FR-8; UJ-1).

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** an EpicSpec and a configured contract-author provider
   **When** I run `specwitness contract epic-7`
   **Then** a draft `.specwitness/contracts/epic-7.yaml` is written whose criteria have stable ids (`E7-01`…), behavioral statements, kind, severity, verifiability — and statements containing implementation coupling (function/class/method references) are flagged in command output for review.
2. **Given** a reviewed draft
   **When** I run `specwitness contract epic-7 --freeze`
   **Then** the fingerprint is computed and stored, status becomes frozen, and the command prints the fingerprint; re-freezing an unchanged frozen contract is idempotent (exit 0, same fingerprint).
3. **Given** `specwitness contract epic-7 --status [--json]`
   **When** invoked (including from a no-TTY agent context)
   **Then** it reports existence, frozen/draft state, version, fingerprint, and criteria counts without prompting (NFR-8; PRD open question 6 satisfied via --json).
4. **Given** verify semantics
   **When** a contract is absent or never frozen
   **Then** `verify` refuses with `HINT:` to run the contract workflow (discipline stance from PRD open question 4).

Clarifications (detail only, no weakening):

- **AC1 you assemble; you do not re-implement.** `ingestEpic` (2.1), the `Contract`/`Criterion` model + `serializeContract`/`parseContract` (2.2), and `invoke()` + role resolution (2.3) are all merged before you start. Your story is the **application service + CLI command** that wires them: ingest → build the provider request → gate-validated draft → assign ids → serialize → write. Do not write a second parser, a second serializer, a second fingerprint, or a second retry loop.
- **AC1 criterion ids come from `buildCriterionId(epicNumber, sequence)`** (`src/domain/ids.ts`, merged) — `E7-01`, epic unpadded, sequence zero-padded to two. Ids are assigned by **you**, sequentially in draft order, **not** by the provider: a provider-chosen id is a provider deciding what survives an amendment (FR-7: "stable IDs ... that survive amendment"). Strip/ignore any id the model returns and say so in the prompt.
- **AC1 the provider drafts, and the schema gate is the only door.** Build the response zod schema from 2.2's criterion model, hand it to `invoke()` with role `contract-author`, and use only the validated `parsed` result. Never parse free-form text yourself; never fall back to a partial draft when the gate fails — a `ProviderError` from `invoke()` propagates and the command writes nothing.
- **AC1 "implementation coupling ... flagged in command output for review" — flagged, never rejected.** This is a heuristic warning printed by the command (e.g. a statement matching `\b\w+\(\)`, `class \w+`, `\w+\.\w+\(`, or naming a file path), listing the criterion ids for the human's review pass. It must **not** fail the command, must **not** be a schema rejection, and must **not** edit the statement. A `structural` criterion may legitimately name a module; the human decides. FR-7's "rejected by schema-level lint **or** flagged for review" — take the flag branch, and say why in the module header.
- **AC1 the file is never silently overwritten.** If `.specwitness/contracts/epic-7.yaml` already exists: a **frozen** contract is refused (amending is 2.7's flow — refuse with a `HINT:` naming `--amend`); an existing **draft** requires an explicit `--force` to regenerate, or the command refuses and says so. Fail closed, then explain. Regenerating over a human's edited draft without asking is the same class of harm as silent tampering.
- **AC1 write atomically.** Write to a temp file in the same directory and rename, so an interrupted generation never leaves a half-written contract that would then fail integrity validation for a reason no one can explain. (`RunStore`'s atomic-finalize discipline in `src/infra/run-store.ts` is the in-repo precedent — read it; note that `RunStore` is the sole writer under `runs/`, and `contracts/` is not its territory, so you write this one yourself.)
- **AC1 `.specwitness/contracts/` already exists** — `specwitness init` (story 1.4, merged) creates it. If it is absent, that means the project was never initialised: refuse with a `HINT:` to run `init`, do not create the tree yourself.
- **AC2 freeze is 2.2's pure function**, called by you with a `Clock`-supplied instant. Idempotence: freezing an already-frozen contract whose content still matches its stored fingerprint prints the same fingerprint and exits 0 — it does **not** bump the version, rewrite timestamps, or rewrite the file. Freezing a frozen contract whose content has *changed* is an `IntegrityError`, not a re-freeze (that is 2.7's amend flow).
- **AC2 print the fingerprint on stdout.** UJ-1's climax is the operator seeing it. Full lowercase hex; do not truncate.
- **AC3 `--status` is prompt-free and agent-callable** (NFR-8, spine "Non-interactive first"). With `--json`, **stdout carries the JSON document and nothing else**; any human rendering goes to stderr. This is exactly the stream discipline `specwitness doctor --json` already implements — read `src/cli/commands/doctor.ts` and `src/cli/doctor/render.ts` and match it, including a `schemaVersion` on the JSON payload.
- **AC3 a missing contract is a normal status answer, not an error.** `--status` on an epic with no contract reports "absent" and exits 0 with valid JSON. Reserve non-zero for genuine failures (bad epic id ⇒ 64 from `normalizeEpicId`; unreadable/corrupt file ⇒ 3).
- **AC4 `verify` does not exist yet** — it is Epic 3. Deliver this AC as a **reusable guard function in `src/authoring/`** (e.g. `assertVerifiableContract(...)`, throwing with the ADR-005/FR-8 wording and a `HINT:` naming the contract workflow) **plus its unit test**, and note in the module header that Epic 3 story 3.7 wires it into the verify path. Do **not** register a `verify` command, not even a stub.
- **`--amend` is NOT yours.** Story 2.7 (dolph) adds it to your command. Leave the seam clean: register options in a way dolph can extend additively, and do not implement, stub, or document an amend path.

### Failure modes to consider

- **No `contract-author` role configured, or its provider binary absent.** UJ-4's edge case: contract *generation* is unavailable, but everything else still works. Refuse this command with a clear `ERROR:`/`HINT:` — never a crash, and never a fabricated contract.
- **A gate exhaustion mid-generation** — `ProviderError`, exit 3, and **no file written or modified**. Assert this; a half-written contract is worse than none.
- **An existing frozen contract** — refused, with a `HINT:` naming the amend flow. An existing draft — refused without `--force`.
- **A tampered contract read during `--status`** — report the mismatch honestly rather than crashing or silently re-fingerprinting.
- **An epic with no stories, or an epic id that does not exist** — 2.1's `IngestError` already names what was searched; let it propagate rather than rewrapping it in a vaguer message.
- **A provider returning zero criteria** — reject: an empty contract would silently PASS every future verify run. This is the highest-severity silent-wrong-answer bug in your story.
- **Very long statements or unusual unicode** — must round-trip through YAML and the fingerprint unchanged; add a case.
- **`process.cwd()` not being the project root** — the merged commands do not search upward (`init`, `doctor`, `report` all use CWD). Follow that convention; `--root` arrives in Epic 3.
- **stdout pollution in `--json` mode** — a stray `console.log` breaks `jq`. Assert stdout is exactly the JSON document.
