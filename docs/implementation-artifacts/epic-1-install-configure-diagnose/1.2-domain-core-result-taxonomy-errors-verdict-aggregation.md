## Story

As a harness automating merges,
I want the closed result taxonomy and a pure mechanical verdict function,
so that outcomes are classified identically everywhere and no AI or I/O can influence a verdict.

## Goal & Context

This story ships the product's non-negotiable core rule: **verdicts are always mechanical** — a pure function, no LLM, no I/O. It defines the closed enums every later epic consumes (criterion statuses, gate results, run outcome), the verdict aggregation function, epic-id normalization, and the tests that pin the exit-code mapping from story 1.1's table. Seven parallel agents in later epics will all import these types; ambiguity here multiplies into cross-story inconsistency later, which is exactly what AD-6/AD-7 exist to prevent.

Wave B story: runs in parallel with 1.3 (`src/config`) on top of merged 1.1. **You own `src/domain` and `src/schemas` (plus extending `src/cli/exit.ts`); do not touch `src/config` or any file story 1.3 owns.**

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** the enums `CriterionStatus {pass|fail|needs_human|skipped|error}`, gate results, and the run outcome union
   **When** aggregation runs over any combination of criterion results
   **Then** it returns FAIL if any `fail`; else infra error if any `error`; else NEEDS_HUMAN if any `needs_human`; else PASS — as a pure function with property-based unit tests (AD-6).
2. **Given** the typed error hierarchy (UsageError, ConfigError, IngestError, IntegrityError, ProviderError, InfraError — gate failure is a stage result, not an exception, per AD-6/AD-7)
   **When** each error type and run outcome maps through the exit table
   **Then** the mapping matches ADR-002 (0/1/2/3/64), a gates-only green run aggregates to PASS, a failed gate aggregates to FAIL+gateFailed, and all of it is covered by tests.
3. **Given** `src/domain/` and `src/schemas/`
   **When** the dependency-direction check runs
   **Then** no import from adapter layers or side-effectful Node built-ins exists (AD-1 enforced by lint/dependency-cruiser in CI).

Clarifications (detail only, no weakening):

- AC1 full aggregation contract (AD-6, ADR-003, questions doc Q45/Q46): the function takes **gate results + criterion results**. Precedence: any gate failed ⇒ `{verdict: FAIL, gateFailed: <gateId>}` (remaining gates and all criteria are reported `skipped` by the caller — the aggregation itself just needs the failed gate); else any criterion `fail` ⇒ FAIL (fail outranks `error` — "fail evidence outranks infra uncertainty", PRD §9); else any `error` ⇒ `{infraError}`; else any `needs_human` ⇒ NEEDS_HUMAN; else PASS. A run with zero criteria and green gates is PASS (gates-only Epic 3 mode). `skipped` criteria never affect the verdict. Severity is recorded but does NOT alter aggregation in V0 (FR-27 assumption).
- AC1 run outcome union is mutually exclusive: `{verdict: 'PASS'|'FAIL'|'NEEDS_HUMAN', gateFailed?: string}` **or** `{infraError: <classification>}` — never both (AD-6).
- AC2: the error classes already exist in `src/domain/errors.ts` (seeded by story 1.1) — do NOT redefine them; extend only if a field is genuinely missing. Your job is the run-outcome→exit mapping added to `src/cli/exit.ts` (`exitCodeForOutcome`) plus exhaustive tests for both mappings.
- AC1 "property-based": use `fast-check` (add as devDependency — justified by this AC; dev-only, not a stack-table change). Properties to pin at minimum: precedence order invariance under permutation of results; monotonicity (adding a `fail` to any input never yields PASS/NEEDS_HUMAN); PASS only when no fail/error/needs_human exists; gateFailed forces FAIL regardless of criteria.

- Divergence between zod enum schemas and domain unions — derive one from the other (e.g. zod enum built from the domain const array) so they cannot drift.

### Debug Log References

**1. `tsc` caught an exhaustiveness bug that `vitest` did not.** The first version of
`exitCodeForOutcome` switched directly on `outcome.verdict`. Because `RunOutcome` is a
discriminated union (via the `infraError?: never` / `verdict?: never` fields),
exhausting the three verdict cases narrows `outcome` itself to `never`, so the default
branch's `outcome.verdict` failed with TS2322 + TS2339. All 217 tests were green at that
moment — vitest does not typecheck. Fixed by destructuring `const { verdict } = outcome`
before the switch, which is the reason the code carries a comment saying so.

**2. Mutation-tested the trust anchor rather than trusting coverage.** Aggregation and
the exit table are the product's trust anchor, so four deliberate defects were injected
and the suite confirmed to fail on each, then reverted:

| Injected defect | Result |
| --- | --- |
| `error` outranks `fail` (reverses PRD §9) | 3 tests fail (incl. a fast-check property) |
| gate precedence removed entirely | 6 tests fail |
| infra outcome returns exit 1 instead of 3 | 8 tests fail |
| `skipped` criterion treated as `needs_human` | 3 tests fail |

Suite restored to 217/217 afterwards. The tests bite; they are not merely present.

**3. Verified alice's scratch-file cleanup could not delete `src/schemas/`.** Story 1.1's
`tests/unit/dependency-rules.test.ts` writes scratch modules under `src/`, and an earlier
version of its cleanup recursively removed `src/schemas` — which would have deleted this
story's files on every `pnpm test`. Read the fix (1.1 commit `5b66e34`) rather than
accepting the summary: `createdDirs` records only directories the test itself created,
cleanup is non-recursive `rmdir`, and `writeModule` refuses to overwrite. Confirmed
`git status` clean of deletions after the first post-rebase test run.

**4. A claim of mine that was wrong, and its correction.** Observed that alice's
`EXIT = Object.freeze({...})` without `as const` would widen `ExitCode` to `number`. It
does not — `Readonly<T>` preserves the literal types, and on TypeScript 6.0.3 `ExitCode`
resolves to `0 | 1 | 2 | 3 | 64` (a `const x: ExitCode = 4` probe fails TS2322). The
claim was made without a compiler to check it against; withdrawn, no change to `exit.ts`.

**5. CI could not be used.** GitHub Actions is disabled at the repo (`on:
workflow_dispatch` only) because the private repo's minutes are exhausted — an
owner-level decision, reported by story 1.1. Per the cohort rule that a harness defect
outside this story stays unfixed, the workflow was neither re-enabled nor edited. All six
workflow steps were run locally instead and pasted into the PR body. **Unverified as a
result: Linux, and Node at exactly 22.12** (local runs are macOS).

### Completion Notes List

- **All six tasks complete.** 127 new tests (90 inherited → 217 total), all green,
  alongside `typecheck`, `depcruise`, `build` and the packed-tarball smoke test.
- **Aggregation is pure, total and mechanical.** `aggregate` takes gate results +
  criterion results, touches no clock, no randomness, no I/O, mutates nothing, and cannot
  throw on any typed input. A `never` guard makes adding a `CriterionStatus` without
  deciding its precedence a compile error rather than a silent PASS.
- **Property-based tests via `fast-check` 4.9.0** (new devDependency, dev-only, cleared
  with story 1.1 which owns `package.json`). Nine properties pin: totality, exactly-one
  union arm, permutation invariance, monotonicity in `fail`, PASS-iff, gate dominance,
  the full precedence ladder, `skipped` inertness, `flaky` inertness, and non-mutation.
- **Deviation from ADR-003, deliberate and flagged.** ADR-003 words the marker as
  `gateFailed: true` plus "the failing gate identified"; the spec and AD-6 specify
  `gateFailed?: string` carrying the gate id. The spec wins (harness precedence rule),
  and the string form loses nothing — a present id is both the signal and the
  identification. Recorded as D1.2-1 in `DECISIONS.md`, surfaced in the PR body, and
  independently seconded by story 1.6's agent.
- **`InfraErrorClassification` excludes `usage`** (D1.2-2). A `UsageError` exits 64 and
  is raised at the CLI edge before a run exists, so it can never be an aggregation
  outcome; including it would create a value whose only correct handling is "impossible".
- **Union exclusivity is enforced by the compiler, not by convention** (D1.2-3):
  `infraError?: never` / `verdict?: never` make `{verdict, infraError}` a type error.
- **`normalizeEpicId` rejects `0` and negatives** (D1.2-5) rather than minting `epic-0`.
  Fail closed, then explain — the error is a `UsageError` with a `HINT`, exit 64.
- **zod enums are derived from the domain arrays**, and a test asserts each schema's
  `.options` deep-equals its source array, so the drift this story's spec names as a
  failure mode fails CI instead of surfacing three epics later.
- **`SCHEMA_VERSIONS` shape was negotiated with story 1.6 before writing it** — a frozen
  `as const satisfies Record<string, number>` literal with a derived `SchemaVersionKey`
  and a `schemaVersionFor()` accessor, so registering an artifact is a genuine one-line
  diff. Deliberately no assert/validate helper: version-mismatch policy is
  artifact-specific and belongs to each artifact's own schema module (agreed with 1.6).
- **`.dependency-cruiser.cjs` was NOT touched.** Task 6 says "add a rule if `src/schemas`
  wasn't covered" — it was covered. Story 1.1 already ships `domain-is-dependency-free`
  and `schemas-core-only` with the correct asymmetry (zod legal in `schemas`, illegal in
  `domain`), so Task 6 became verification rather than authorship. One owner per guardrail.
- **`src/cli/exit.ts` was extended additively only**: one type-only import plus
  `exitCodeForOutcome` at the bottom. `EXIT`, `ExitCode`, `exitCodeForError` and
  `applyExitCode` are byte-identical to 1.1. No `process.exit` / `process.exitCode`
  anywhere in this diff — 1.1's scan test stays green.
- **Nothing outside the declared scope was touched**: no `src/config` (story 1.3), no
  `src/infra` or `src/cli/commands` (wave C), no `docs/planning-artifacts/`, no `docs/adr/`,
  and only this story's own row in `sprint-status.yaml`.
