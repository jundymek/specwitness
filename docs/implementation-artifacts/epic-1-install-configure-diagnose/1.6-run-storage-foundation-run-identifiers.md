## Story

As a harness consuming results,
I want every run persisted under `.specwitness/runs/<run-id>/` with canonical ids and timestamps,
so that later epics write results/evidence into a stable, local-first layout (FR-31 foundation).

## Goal & Context

Foundation for everything Epics 3–6 persist: the canonical run-id format, the `Clock`/`Ids` ports (AD-9 — no real time/randomness in unit tests, ever), and `RunStore` — the SOLE writer under `.specwitness/runs/<run-id>/` (AD-8). The manifest skeleton it writes (fsynced BEFORE any resource use) is what makes crash-safe cleanup possible later (`specwitness clean`, story 3.2 — kill -9 must never lose track of a worktree or process group). Also ships the `report <run-id>` stub proving stored runs are locatable and renderable.

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** a new run
   **When** the run store creates it
   **Then** the id matches `run-<YYYYMMDDTHHmmssZ>-<4 base36>`, a `manifest.json` skeleton exists before any resource use, and all timestamps are ISO-8601 UTC.
2. **Given** `Clock` and `Ids` ports
   **When** domain/application tests run
   **Then** both are injectable fakes (no real time/randomness in unit tests) per AD-9.
3. **Given** run directories exist
   **When** `specwitness report <run-id>` (stub) is invoked
   **Then** stored run metadata is located and rendered (full rendering arrives in Epic 3).

Clarifications (detail only, no weakening):

- AC1 id format (spine conventions row, normative): `run-<YYYYMMDDTHHmmssZ>-<4 random base36>` — compact UTC timestamp (e.g. `run-20260830T142501Z-a3f9`), 4 lowercase base36 chars from the `Ids` port. Provide parse/validate helpers; ids sort chronologically by construction.
- AC1 manifest skeleton (schemaVersion per AD-5; Epic 3 story 3.2 extends additively): `{schemaVersion: 1, runId, createdAt: <ISO-8601 UTC>, epic: string|null, worktrees: [], processGroups: [], reaped: false}`. "Before any resource use" = `createRun` returns only after the manifest file is written AND fsynced (file + containing directory) — this is the crash-durability discipline AD-8 names; kill -9 immediately after `createRun` must leave a readable manifest.
- AC2: ports are interfaces in `src/domain/ports.ts` (`Clock.now(): Date` or ISO string, `Ids.randomBase36(length): string`); real implementations live in `src/infra/`; fakes (`FixedClock`, `SequenceIds`) live with tests and make run ids fully deterministic in unit tests.
- AC3 stub scope: accepts a run-id argument only (epic-name lookup arrives Epic 3 story 3.5); locates `.specwitness/runs/<run-id>/manifest.json` via RunStore, renders manifest metadata (runId, createdAt, epic, reaped) + whether `result.json` exists ("no result yet — run verification arrives in Epic 3"); unknown/invalid run-id ⇒ `ERROR:` naming what was searched + `HINT:` (exit 3); malformed id string ⇒ `UsageError` (exit 64).

### Codex Review — 3 findings, all fixed

All three were real defects that the test suite had not covered. Each fix was
verified by reverting it and confirming the new test fails.

1. **[P1] `createRun` did not fsync the runs root.** Syncing the run directory
   persists `manifest.json`'s entry *within* it, but the run directory's own
   entry lives in the parent. After a crash the entire run directory could
   therefore disappear even though `createRun` had resolved — defeating the
   exact guarantee this story exists to provide, since `clean` would have
   nothing left to replay. Now fsyncs `runsRoot` as part of the durability
   sequence. This was the most valuable of the three: I had reasoned carefully
   about file-versus-directory fsync and still stopped one level too shallow.

2. **[P2] `hasResult` swallowed every error as "no result".** A `stat` failing
   with `EACCES`/`EIO`/`ENOTDIR` returned `false`, so `report` would exit 0
   claiming the run had no result — an infrastructure failure reported as a
   product answer, which this project treats as a first-order defect. Now only
   `ENOENT` means false; everything else raises `InfraError`.

3. **[P2] The manifest timestamp accepted impossible dates.** `Date.parse`
   accepts `2026-02-31T14:25:01.123Z` and silently normalises it to 3 March
   (likewise 29 February in a common year becomes 1 March), so the schema was
   weaker than the `runId` validator sitting beside it and would accept a
   corrupt manifest meaning a different instant than it claimed. Now
   round-trips the components through `Date.UTC`, the same technique
   `parseRunId` uses. I verified the normalisation empirically before
   accepting this finding rather than trusting the claim.

A directory fsync returning `EINVAL` (filesystems that do not implement it) is
tolerated rather than failing the run — it is not a durability failure on those
platforms. Every other fsync error propagates as `InfraError`.

### Completion Notes List


**All four tasks complete; all three ACs met.** 118 tests added (341 total,
all green). TDD throughout: every test was run and seen RED before its
implementation existed.

- **AC1 — id format, manifest skeleton, ISO-8601 UTC.** `run-<YYYYMMDDTHHmmssZ>-<4 base36>`
  per the spine's normative Identifiers row. Ids sort chronologically as plain
  strings by construction. `createRun` returns only after the manifest is
  written **and fsynced — file first, then its containing directory**. The
  directory fsync is the step usually missed: fsyncing a file guarantees its
  contents survive, not that its name still appears in the directory, so
  without it a crashed run can return as an empty directory — precisely the
  case story 3.2's `clean` cannot recover from.

- **AC2 — injectable ports.** `Clock`/`Ids` are interfaces in
  `src/domain/ports.ts` with zero implementations and zero imports.
  `FixedClock`/`SequenceIds`/`ConstantIds` live in `tests/fakes/ports.ts`
  (deliberately not shipped in `src/`: a fake in the package is a fake someone
  eventually injects in production). Every unit test asserts exact id strings
  rather than regex shapes.

- **AC3 — `report <run-id>`.** Renders runId, createdAt, epic, reaped, and
  whether `result.json` exists. Exit 0 / 3 (unknown run, uninitialised
  project) / 64 (malformed id). Id validation happens *before* any filesystem
  access, so a typo is exit 64 rather than exit 3 — exit 3 would tell a
  harness the environment is broken and that retrying might help.

**Decisions worth a reviewer's attention:**

- **Read paths never create directories.** Only `createRun` mkdirs.
  `listRuns()` on a missing root returns `[]`; `runDir()` is pure; `report` on
  an uninitialised project exits 3 touching nothing. Surfaced by arnold (1.4),
  whose `init` scaffolded a live `.specwitness/` into the repo on every test
  run because `runCli` used `cwd: REPO_ROOT`. His fix gives the suite a temp
  cwd, but that removes the blast radius, not the defect class — a mutating
  read would then corrupt a temp dir invisibly instead of the repo visibly. So
  the invariant is asserted directly (`report` leaves `.specwitness/` absent).

- **`runDir()` validates before joining.** It is the single
  path-construction point (AD-8), so validating there means no caller can
  smuggle a traversal through any other method. `../../etc/passwd` and
  `run-…/../..` are rejected.

- **Collision fails closed.** The per-run `mkdir` is deliberately
  non-recursive, so a same-second/same-suffix collision raises `InfraError`
  instead of two runs overwriting each other's evidence. Verified that the
  first run's manifest is intact after a refused second.

- **`parseInt` saturation avoided structurally.** bob hit this as a real P2 in
  `domain/ids.ts` (two different epics normalising to one canonical id).
  Rather than guarding after conversion, the run-id matcher is anchored with
  fixed field widths, so an over-long digit run fails on shape and never
  reaches a numeric conversion. A 500-digit input is tested. `Number.isSafeInteger`
  guards were considered and deliberately **not** added: every field is 2–4
  digits by the pattern, so saturation is unreachable and the guard would be
  dead code implying a risk that does not exist. Real calendar validation
  (rejecting 31 February, 29 February in a common year) is what actually
  matters and is implemented by round-tripping the components through
  `Date.UTC`.

- **Base36 uses rejection sampling.** 256 is not a multiple of 36, so a plain
  modulo would make `0`-`3` ~1.4% likelier than other characters. Bytes ≥ 252
  are discarded. Both boundaries are tested (251 accepted, 252-255 rejected).

- **Version-mismatch policy lives in `schemas/manifest.ts`, not the registry.**
  Agreed explicitly with bob (1.2): what a mismatch *means* is
  artifact-specific — a manifest wants "a newer specwitness wrote this", a
  contract may want to migrate or refuse — so a shared helper would freeze one
  answer for all artifacts. His `schemaVersionFor()` accessor is used rather
  than indexing `SCHEMA_VERSIONS` directly.

- **`.strict()` on the manifest schema.** An unknown key means a newer writer,
  and silently dropping it could discard a worktree path story 3.2 needs to
  clean up.
