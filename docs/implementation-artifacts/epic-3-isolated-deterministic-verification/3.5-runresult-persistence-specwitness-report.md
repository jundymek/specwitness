## Story

As a harness and a human revisiting results,
I want the complete RunResult persisted per run and re-renderable,
so that evidence outlives the terminal session (FR-31, FR-30 partial; AR-4).

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** a completed run (any outcome)
   **When** persistence executes
   **Then** `.specwitness/runs/<run-id>/result.json` (schemaVersion, epic, base/head SHAs, verdict/infra outcome, stage timeline, gate results, criterion results with expected/actual and evidence refs, provider usage, timestamps) plus evidence files exist locally.
2. **Given** `specwitness report epic-7` or `specwitness report <run-id>` (`--json`)

   **When** the JSON snapshot test runs
   **Then** unintended shape changes fail CI (NFR-7).

Clarifications (detail only, no weakening):

- **AC1 "any outcome" includes the infra ones.** A run that ended `{infraError: 'integrity'}` before a worktree existed still persists a `result.json` — that is what makes a failed run diagnosable later, and `report` must render it. Test the PASS, FAIL+`gateFailed`, NEEDS_HUMAN and infra paths.
- **AC1 the atomic finalize belongs in `src/infra/run-store.ts`, and the file reserves it for you by name.** Its header lists AD-8's two write disciplines and says of the second: *"Atomic finalize (stage-and-rename) for `result.json`. Deliberately NOT implemented here: its consumer arrives in story 3.5."* Implement it there — **not in the pipeline, not in a new module**. RunStore is the **sole writer** under `.specwitness/runs/<run-id>/`, enforced as a grep-level rule: outside that file no module may construct a path under `.specwitness/runs`.
- **AC1 "atomic" means write to a temp name in the same directory, fsync the file, rename over the target, then fsync the directory.** The rename is what makes a reader see either the old file or the complete new one, never a half-written one. `#writeDurably` and `#syncDirectory` already exist in that file — reuse them rather than opening a second write path.
- **AC1 carries an inherited defect you should fix while you are in this territory — decide explicitly.** `src/authoring/contract-file.ts` (story 2.6) runs `syncDirectory(directory)` **after** `rename`, inside the same `try`; a post-rename sync failure raises *"could not write …"* while the file has in fact been replaced (Epic 2 retro §5a defect ii). It is the same stage-and-rename shape you are about to implement, in the module whose whole purpose is that state is never ambiguous. **Recommended disposition: 3.7 (dolph) fixes it**, since his integrity stage reads the file that writer produces — but **do not repeat the bug**: in your finalize, treat a post-rename failure as a **distinct, non-fatal condition** (the write committed; only the durability barrier did not) and say so in the module header. If you and dolph agree in intent-sync that you fix it instead, that is fine — **just do not leave it unowned**.
- **AC1 `schemaVersion` — you register `jsonReport`.** `src/schemas/versions.ts`'s comment already reserves the key (*"Epic 3 adds `jsonReport`"*), and the registry is `as const satisfies Record<string, number>` so adding a key is a genuine one-line diff. **Do not bump `runManifest`** — its own header says populating the reserved arrays (bob's work) does not bump it, and your `result.json` is a *separate artifact* with its own version, not a manifest change.

Normalize the epic id with the merged `normalizeEpicId` (`7` ≡ `epic-7` ≡ `epic-07`). **Distinguish "no such epic" from "epic exists, no runs" from "runs exist, none with a result"** — three different operator situations with three different remedies.
- **AC2 "without re-executing anything" is absolute** (Q52). `report` is a **pure read**: it creates no directory, not even the runs root, not even when the project has never been initialised — the merged stub already guarantees this and there is a test for it. ### Failure modes (the ones that would matter in production)

- **A half-written `result.json`.** `report` renders a partial verdict as complete. Stage-and-rename exists for exactly this.
- **A successful write reported as a failure.** The inherited §5a defect ii shape: the operator believes nothing changed while the file has in fact been replaced — a lie about state in the module whose entire purpose is that state is never ambiguous.
- **Two serializations.** If `--json` and `result.json` are produced by different code paths they will drift, and the byte-equality test will be the only thing that notices — after it has already broken.
- **An absolute evidence path.** The run directory stops being portable, silently, and only when someone copies it.
- **`report` scaffolding storage.** A read that creates the runs root turns "you have no runs" into "you have an empty runs directory", and it does it in an uninitialised project. The merged stub is explicit that this must not happen.
- **A `runManifest` version bump.** Makes every existing manifest unreadable — including the ones a crashed run left for `clean`.

### Security

- **Evidence is redacted at capture** (AD-10, pamela's constructors). You persist what you are given and **never re-redact** — but equally, never bypass: everything you write comes from the model, not from a raw stream you fetched yourself.
- **`result.json` may contain project output.** That is why capture-time redaction exists. Your snapshot fixture should include a would-be secret so the persisted document demonstrably does not carry it.
- **NFR-1.** Nothing reads `~/.claude/`, `~/.codex/` or any credential store; `tests/unit/doctor/credential-boundary.test.ts` is the AST guard.
- **Path handling.** `RunStore.runDir()` validates the run id before joining, which is what stops a traversal reaching the filesystem through any store method. Route every path through it; never `join` a run path yourself.
