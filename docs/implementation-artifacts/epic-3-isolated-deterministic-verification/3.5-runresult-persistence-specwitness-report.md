## Story

- **AC1 "atomic" means write to a temp name in the same directory, fsync the file, rename over the target, then fsync the directory.** The rename is what makes a reader see either the old file or the complete new one, never a half-written one. `#writeDurably` and `#syncDirectory` already exist in that file — reuse them rather than opening a second write path.

### Failure modes (the ones that would matter in production)

- **A half-written `result.json`.** `report` renders a partial verdict as complete. Stage-and-rename exists for exactly this.
- **A successful write reported as a failure.** The inherited §5a defect ii shape: the operator believes nothing changed while the file has in fact been replaced — a lie about state in the module whose entire purpose is that state is never ambiguous.
- **Two serializations.** If `--json` and `result.json` are produced by different code paths they will drift, and the byte-equality test will be the only thing that notices — after it has already broken.
- **An absolute evidence path.** The run directory stops being portable, silently, and only when someone copies it.
- **`report` scaffolding storage.** A read that creates the runs root turns "you have no runs" into "you have an empty runs directory", and it does it in an uninitialised project. The merged stub is explicit that this must not happen.
- **A `runManifest` version bump.** Makes every existing manifest unreadable — including the ones a crashed run left for `clean`.

### Security

- **Evidence is redacted at capture** (AD-10, pamela's constructors). You persist what you are given and **never re-redact** — but equally, never bypass: everything you write comes from the model, not from a raw stream you fetched yourself.
- **`result.json` may contain project output.** That is why capture-time redaction exists. Your snapshot fixture should include a would-be secret so the persisted document demonstrably does not carry it.
- **NFR-1.** Nothing reads `~/.claude/`, `~/.codex/` or any credential store; `tests/unit/doctor/credential-boundary.test.ts` is the AST guard.
- **Path handling.** `RunStore.runDir()` validates the run id before joining, which is what stops a traversal reaching the filesystem through any store method. Route every path through it; never `join` a run path yourself.

**A test that revealed a real design constraint.** A round-trip assertion
(`serialize → parse → serialize` reproduces the bytes) failed. Cause: zod rebuilds a
validated object in **schema declaration order**, which is not the order the merged
evidence constructors build their members in. Values survive; bytes do not. This directly
threatened story 3.7's end-to-end assertion that `report --json` is byte-identical to
`result.json`, and it drove the decision to **echo the stored bytes** rather than
re-serialize (see DECISIONS.md D19). Both halves are now pinned by tests so the property
stays known rather than becoming a trap.

### Completion Notes List

- **`src/schemas/result.ts` is THE serializer for the repository.** `RunStore` persists
  with it and story 3.6's `--json` renderer calls it and returns the result unchanged, so
  the harness contract's promise that the two are the same bytes (Q53) is structural
  rather than a coincidence two code paths keep agreeing on. Placement in `schemas/`
  rather than `infra/` is what makes it importable by the report layer at all.
- **The finalize reuses story 3.2's `#writeDurably` rather than opening a second write
  path.** Once that helper stages, fsyncs, renames and fsyncs the directory, it *is* the
  atomic finalize AD-8 names. Consequence: the real staging name is `.result.json.writing`,
  not the `.result.json.tmp` reserved earlier by agreement — the pattern check covers it,
  and the now-vestigial constant is labelled so nobody removes that check believing the
  constant covers `result.json`.
- **A post-rename barrier failure is fatal here, and that is a revision.** The original
  decision said "non-fatal". Reading story 3.2's merged fix showed the defect was never
  fatality — it was *describing a committed write as a failed one*. Three modules in this
  epic now share that rule with deliberately different fatality choices; the table is in
  DECISIONS.md D4. For `result.json` fatal is right, because the whole point of persisting
  is that the run survives the crash it was written for — and it costs nothing, since the
  failure lands on the `persist` timeline entry and never touches the verdict.
- **The persist stage takes a narrow function port, not `RunStore`.** No path under
  `.specwitness/runs/` is constructible from `src/pipeline/**` at all, so AD-8's
  sole-writer rule holds by construction rather than by review. Story 3.4 chose the same
  shape independently.
- **Every outcome reaches storage, and the infra path does so by a non-obvious route.**
  An early throw skips the persist stage entirely, so `{infraError}` runs are stored only
  by the post-teardown `onComplete` write. Remove that callback and the failures most
  worth reading about would be the only ones with no record. Asserted explicitly.
- **`report --json` validates then echoes the file's own bytes.** Validating means a
  harness never receives something off-schema; echoing raw bytes rather than
  re-serializing is what makes byte-equality true by construction. A run with no stored
  result exits 3 with an **empty** stdout — a parseable non-result would be worse than
  nothing.
- **`report`'s no-execution guarantee is asserted structurally** (the module cannot reach
  a process runner) and, through the built binary, by comparing the run directory's full
  listing, sizes and mtimes before and after. Both are stronger than the injected throwing
  runner the spec suggested, and the second also catches a write nobody intended.
- **CLOSED BY THE FOLLOW-UP (2026-09-01), after story 3.6 merged.** Task 4's
  *"Import chuck's renderers"* is now ticked: `report` calls `renderTerminal` from
  `src/report/index.ts`, and a test asserts the command's output equals the renderer's
  **exactly**, so `report` cannot quietly become a second renderer. A run that stored
  nothing still answers with exit 0 and its manifest facts — deliberately unlike
  `--json`, which must emit a document or nothing. The original deferral and its
  reasoning are kept below, because the record of *why* it shipped unwired is worth
  more than a tidy checklist.
