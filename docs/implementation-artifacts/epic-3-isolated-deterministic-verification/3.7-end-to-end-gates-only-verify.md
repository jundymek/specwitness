## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** a fixture project with a frozen contract and passing gates
   **When** `specwitness verify epic-1 --json` runs
   **Then** exit 0 with verdict PASS, criteria reported `skipped`/`needs_human` as appropriate (no probes yet), and a persisted run.
2. **Given** the same fixture with a broken build
   **When** verify runs
   **Then** exit 1, `gateFailed`, matching ADR-003 exactly.
3. **Given** a fixture where the worktree cannot be created (corrupt ref)
   **When** verify runs
   **Then** exit 3 InfraError with `HINT:` — demonstrating the three-way classification live (FR-22).

Clarifications (detail only, no weakening):

- **All three ACs are asserted against the BUILT BINARY, not against imported functions.** `tests/setup/build-cli.ts` already runs `tsup` as global setup so `dist/cli.js` exists before integration tests; `tests/integration/cli.test.ts` is the merged pattern. This matters because exit codes, stream separation and the shebang are only real at the process boundary — an in-process test can assert a returned number while the shipped binary exits differently.
- **The three ACs are the three-way classification, and each must assert BOTH the right answer and the absence of the wrong ones.** That is the whole product promise made testable:
  - AC1 exit **0**, `verdict: "PASS"`, no `gateFailed`, no `infraError`;
  - AC2 exit **1**, `verdict: "FAIL"`, `gateFailed` naming the failing gate, **not** exit 3;
  - AC3 exit **3**, an `infraError` classification, **no verdict at all**, and `ERROR:`/`HINT:` on stderr.
  A test that only asserts the expected code would pass if every run returned it.
- **AC1 "criteria reported `skipped`/`needs_human` as appropriate".** No probes exist in Epic 3, so a frozen contract's criteria are reported `skipped` — except those whose `verifiability` is `human`, which are `needs_human` (Q39: needs_human has exactly two triggers, and criterion-level verifiability is one). **This changes the verdict**: a contract containing a `human` criterion yields **NEEDS_HUMAN (exit 2)**, not PASS, because `aggregate` ranks `needs_human` above PASS. So AC1's fixture contract must contain **no** `human`-verifiability criteria — otherwise the AC is unsatisfiable. **State this in your fixture's comments**, and add a fourth test proving the NEEDS_HUMAN path (exit 2) with a contract that does have one: it is the only remaining arm of the exit table, it costs one fixture, and Epic 3 is the last chance to prove it before Epic 4 depends on it.
- **AC1 "a persisted run"**: `.specwitness/runs/<run-id>/result.json` exists afterwards, parses, and `specwitness report <run-id>` re-renders it **without re-executing anything** (Q52). Assert the re-render too — that is FR-31's actual promise and it costs one more command.
- **AC1 `--json` byte-equality, proved end-to-end.** stdout must be `JSON.parse`-able, must be **the only thing on stdout**, and must be **byte-equal to the persisted `result.json`**. chuck (3.6) owns the unit-level assertion; **you own the end-to-end one through the built binary**, which is the version that catches a stray write nobody noticed in a unit test.
- **AC3 "corrupt ref" — pick a case that actually reaches the worktree stage.** A `--head` naming a ref that does not exist fails at *resolve*, which is also exit 3 but is a different code path from "the worktree cannot be created". Cover both, and say in your PR body which is which; the AC's parenthetical names the ref case, and the epics file's own AC1 for story 3.1 names the missing-ref-with-`git fetch`-hint case. Both are InfraError; neither may ever be FAIL.
- **AC2 "matching ADR-003 exactly"**: Verdict FAIL, the failing gate identified, remaining gates and **all criteria reported `skipped`**, the gate's output as evidence, exit code 1. Assert each clause. Note that `gateFailed` is a **string carrying the gate id**, not a boolean — the merged `src/domain/run-outcome.ts` implements it that way and ADR-003's prose is the stale half (carried action item A3).
- **The verify guard is merged and waiting for you — wire it, do not reinvent it.** `assertVerifiableContract` in `src/authoring/verifiable.ts` was built by story 2.6 explicitly for this story; its header says so by name: *"`specwitness verify` does not exist yet — it is Epic 3, and story 3.7 wires this guard into the verify pipeline."* Three refusals with three distinct hints — absent, never-frozen, tampered — and **`tampered` must never be reported as "not frozen yet"** (that wording invites the operator to freeze over the edit, laundering a tamper into a legitimate contract). Add a test per refusal.
- **The AD-1 seam you must build: the CLI edge loads and verifies the contract, then passes the result INTO the pipeline.** `src/pipeline/**` may not import `src/authoring/**` (application layers do not import each other; pamela's `pipeline-layer` rule enforces it). So `verify` — at the edge, where reaching into any layer is legal — loads config, loads the contract, calls `assertVerifiableContract`, resolves refs via alice's `Vcs`, assembles the stage list, and runs pamela's pipeline. **pamela publishes this seam in wave A intent-sync; confirm it against her merged source.**
- **Exit codes come only from `src/cli/exit.ts`.** `exitCodeForOutcome(outcome)` maps a completed run; `exitCodeForError(err)` maps a thrown one and **fails closed** (anything unrecognised ⇒ 3). `tests/unit/exit-location.test.ts` scans `src/**` for `process.exit(`/`process.exitCode` and will fail your PR if you write one. `src/cli/main.ts` already has the single broad catch — extend nothing about it beyond your registration line.
- **`verify` is prompt-free** (Conventions: agent-callable commands make no TTY assumptions). No confirmations, ever — it is the command a harness runs unattended.
- **Flags:** `--root`, `--base`, `--head`, `--json`, and the epic argument (normalized by the merged `normalizeEpicId`). A malformed flag value is a **`UsageError` (exit 64)**, raised at the edge — deliberately outside 0–3 so a typo can never be mistaken for NEEDS_HUMAN (ADR-002). Assert that too.
- **The inherited defect this story should close.** Epic 2 retro §5a defect (ii): `src/authoring/contract-file.ts` runs `syncDirectory(directory)` **after** `rename` inside the same `try`, so a post-rename sync failure reports *"could not write .specwitness/contracts/<epic>.yaml"* while the file has in fact been replaced — a lie about state in the module whose entire purpose is that state is never ambiguous. **The owner assigned this to you on 2026-08-31 — it is not optional and it is not negotiable in intent-sync.** Your integrity stage reads the file that writer produces, so you are in the territory. The fix is small: treat post-rename failures as a distinct, non-fatal condition (the write committed; only the durability barrier did not), with a red-first regression test that proves a post-rename sync failure no longer reports the write as failed. Report it in your PR body as a named deliverable of this story. (The other §5a defect, `fenceMask` closing on a tagged inner fence in `src/ingest/bmad-v6/markdown.ts`, is **out of scope for this epic** — no Epic 3 story ingests markdown; it stays a named follow-up.)
- **Golden Corpus fixtures are Epic 6.** `fixtures/corpus/` does not exist yet, and the epics file's references to "Golden Corpus fixture 7/8" are forward references. **Use inline fixtures built by your tests and say so plainly in your PR body**, so nobody reads a passing suite as corpus coverage.

### Failure modes (the ones that would matter in production)

- **An infra failure reported as exit 1.** The first-order defect of this project. A harness reads "your branch has defects" and blocks a mergeable branch, or a developer hunts a bug that does not exist.
- **A gate failure reported as exit 3.** The mirror image: the harness retries a branch that will never build.
- **A tampered contract reported as "not frozen yet".** Invites the operator to freeze over the edit, laundering a tamper into a legitimate contract and destroying the only evidence it happened (ADR-005).
- **Anything but JSON on stdout under `--json`.** Breaks `JSON.parse` for every consumer.
- **A verify that touches the invoking workspace.** FR-19's whole promise, and the reason the kill-mid-run test exists.
- **Verifying the wrong tree when invoked from a linked worktree.** Your manual testing should include this case explicitly — it is where every agent in this cohort actually works, and the failure is silent.
- **Claiming a gate green that no agent could run.** CI, Linux and Node 22.12 are pending-owner. Reporting them as passed would be the one closure defect that outlives the epic.

### Security

- **AD-3 end-to-end.** Gate commands are `DeclaredCommand`s from Project Config; `git` and provider binaries are trusted-tool spawns with fixed argv; no string from a contract, a provider or a plan is interpolated into a shell. Your wiring is where a shortcut would be tempting and would undo the whole boundary. `tests/unit/config/boundary-scan.test.ts` scans every source file outside `src/config/` for casts and deep imports.
- **ADR-005.** `verify` never mutates a contract, never freezes, never amends. It reads and refuses.
- **NFR-1.** Nothing reads `~/.claude/`, `~/.codex/` or any credential store.
- **No AI on this path.** Epic 3's verify is entirely AI-free (FR-18, Q66): a frozen contract plus gates execute with **zero provider calls**. Assert it — inject a provider that throws, and prove nothing called it.

### Debug Log References

Five things were found by RUNNING the command rather than by reading code. Three
were in files owned by other stories and were escalated rather than patched; the
supervisor routed each to its owner, who fixed it.

1. **A `verifiability: human` criterion verified PASS, exit 0** — `verifiability` was
   dropped when the integrity stage built `ContractCriterionRef`, so every criterion
   derived from zero attempts as `skipped`, and `skipped` is inert. Q39's first
   NEEDS_HUMAN trigger was unreachable, which made this story's exit-2 arm
   unsatisfiable. Escalated with the evidence chain; fixed by story 3.3 (#32).

2. **Every stage hint was discarded: an exit-3 run printed `stderr bytes: 0`.** The
   pipeline turns a stage throw into an outcome, so `main.ts`'s printer never runs for
   it, and `StageTimelineEntry` had nowhere to carry `hint`. The tampered-contract case
   is where that costs most: the operator was told the content no longer matches its
   fingerprint and was NOT told about `--amend`, so the obvious next move is `--freeze`
   — laundering the tamper ADR-005 exists to make detectable. Fixed by story 3.3 (#32);
   printing the pair at the edge is this story's (`reportInfraFailure`).

3. **An unusable `TMPDIR` escaped as a raw errno with no remedy** — the worktree
   container is created by an unwrapped `mkdtemp`, so ENOSPC / EACCES / ENOTDIR surface
   as `ENOTDIR: ... mkdtemp '...'` with no hint, although story 3.1 already publishes
   the right words for the failure one step later. Story 3.1 took the wrap (#36), which
   merged immediately before this story; **the deferred hint assertion is now enabled**
   and asserts the remedy rather than only the diagnosis.

4. **A kill in the pre-registration window leaves an empty container `clean` cannot
   reap** — measured 3 runs: reaped, reaped, left behind. `clean` reaps by path, and
   path-only removal takes its no-op branch when the worktree was never registered, so
   the container removal after it is skipped. One empty temp directory, never a checkout
   and never a registration. Reported to stories 3.1 and 3.2; the test asserts "gone, or
   empty if present" rather than a flaky "gone".

5. **Ctrl+C mid-run tells the operator nothing** (manual pty, Task 6). SpecWitness dies
   with exit 130 (a signal death, not a returned code — the frozen table is unaffected),
   the detached gate survives by story 3.2's design, `git status` is unchanged, and
   `clean` afterwards reaps everything. The gap is that nothing says so. Not fixed here:
   a SIGINT handler on the verify path is a design question story 3.2 named as belonging
   to an ADR or Epic 4. See `DECISIONS.md` 3.7-O2.

Two of my own measurements were wrong before they were right, and both corrections
