## Story

As a supervisor reading results inside an agent context,
I want the sectioned terminal report and `--json` derived from one RunResult,
so that human and machine views never drift and output stays bounded (FR-29, FR-30, AD-11, NFR-8; brief §36–37).

## Acceptance Criteria

From `docs/planning-artifacts/epics.md` (authoritative — expand, never weaken):

1. **Given** a RunResult
   **When** the terminal renderer runs
   **Then** it prints: contract status + fingerprint validity, base/head, environment summary, per-gate ✓/✗, per-criterion ✓/✗/? with one-line summaries, counts (PASS/FAIL/NEEDS_HUMAN), VERDICT, and the run evidence path — with any long output truncated to a cap plus a pointer to the full file.
2. **Given** `--json`
   **When** verify or report runs
   **Then** stdout carries only the JSON document (parseable by `JSON.parse`), everything human goes to stderr, and content equals the persisted `result.json`.
3. **Given** both renderers
   **When** tested
   **Then** neither computes facts absent from RunResult (renderers are pure over the model).

Clarifications (detail only, no weakening):

- **AC3 is the load-bearing one, and it is a design constraint before it is a test.** A renderer that computes anything — a count, a duration total, "which gate failed", a pass/fail ratio — has made a fact the JSON view does not have, and the two views have already drifted. **When you find yourself wanting to compute, the fact belongs in pamela's `RunResult`** — and that is a message to her or a follow-up story, **never a parallel edit to `src/domain/run-result.ts`**. Say in your PR body which facts (if any) you had to request.
  - **Counts are the case that will tempt you.** AC1 requires printing counts of PASS/FAIL/NEEDS_HUMAN. Summing an array in a renderer is exactly the drift AD-11 forbids — the terminal view would show a count the JSON consumer has to recompute, and the two summations could disagree the day a status is added. **Ask pamela for counts in the model**, or agree in writing that a shared pure helper in `src/domain/` computes them for both renderers. Either is fine; a renderer-local sum is not.
- **AC3's test is a property, not a spot check.** Prove it structurally: your renderers take a `RunResult` and nothing else — no `Clock`, no filesystem, no config, no process — so a fact they do not receive is a fact they cannot invent. Make that visible in the signatures, then assert it: a renderer given a `RunResult` twice produces byte-identical output both times (no clock, no randomness), and every number it prints is traceable to a field.
- **AC2 "content equals the persisted `result.json`" means BYTE-equal, and the test is yours.** Not "parses to the same object" — byte-equal, because the harness may diff, hash or cache the document (Q53/Q55: "the same document on stdout with `--json`"). Write the assertion against the real persisted bytes, not against a re-serialization. **Ownership, agreed across the epic:** rambo (3.5) persists, you render, **the byte-equality unit/integration test lives with you**, and predator (3.7) proves it end-to-end through the built binary.
- **AC2's stream discipline is the harness contract.** With `--json`: **stdout carries the JSON document and nothing else** — no progress lines, no warnings, no trailing banner. Everything human goes to **stderr**. `src/cli/commands/doctor.ts` is the merged precedent; match it. A single stray `console.log` breaks `JSON.parse` for every consumer, so assert stdout **exactly**, not with `toContain`.
- **AC1 "bounded" is NFR-8, and the caller is often an agent context.** A `npm test` failure can be megabytes; an unbounded report would flood a supervisor's context window. Use **pamela's cap and truncation marker** (`domain/evidence.ts`, wave A) — do not define a second cap. The marker points at the full file **by relative path from the run directory** (Q48), so the pointer stays valid after the directory is moved.
- **AC1 "contract status + fingerprint validity"** comes from the model, not from re-reading the contract file. If `RunResult` does not carry it, that is a request to pamela — **not** a filesystem read in a renderer. The same applies to the environment summary.
- **AC1's ✓/✗/? vocabulary maps to the merged closed enums**, and every switch over them gets a `never` exhaustiveness check (`src/domain/verdict.ts` and `src/cli/exit.ts` both show the pattern):
  - `CriterionStatus`: `pass` ✓ · `fail` ✗ · `needs_human` ? · `skipped` · `error` — **and `error` must be visually distinct from `fail`**. One is "the branch is wrong", the other is "we could not look". Rendering them the same way undoes the classification the whole epic exists to preserve.
  - `GateStatus`: `pass` ✓ · `fail` ✗ · `skipped`.
  - `flaky: true` on a passing criterion is **surfaced, always** (FR-32, AD-9: "a retry-pass is surfaced as `flaky: true` in report and JSON — aggregation treats it as pass, visibility is mandatory"). A flaky pass rendered as a clean pass is the one rendering bug that hides a real defect class.
- **Terminal output is plain text, and must remain readable when it is not a TTY.** The caller is frequently a pipe or an agent's capture buffer. If you use colour, it must be conditional and its absence must lose no information — a report that distinguishes `fail` from `error` **only** by colour fails AC1 when piped. Prefer glyphs and words.
- **`--json` is a flag on `verify` and `report`, but you do not register either command.** Verify is predator's (3.7); report is rambo's (3.5). You export the renderers they call.

### Architecture compliance

- **AD-11.** One `RunResult`, many renderers; no renderer computes its own facts; bounded terminal output with a pointer to the full file; the JSON is snapshot-tested (rambo owns the snapshot; you own byte-equality).
- **AD-10.** Evidence is redacted **at capture**, in pamela's constructors. **Renderers never re-redact** — and equally never un-redact or reconstruct. If a value looks redacted, print it redacted.
- **AD-1.** `src/report/**` may import `domain`, `schemas`, siblings and npm — nothing else. Your new rule enforces it.
- **AD-6.** Closed enums, with `never` exhaustiveness checks on every switch.
- **AD-9.** No clock, no randomness — a renderer that reads the clock is not deterministic and cannot be snapshot-tested.
- **Conventions.** ISO-8601 UTC timestamps rendered as stored; `durationMs` integer ms; kebab-case filenames; no `process.exit` (`tests/unit/exit-location.test.ts` scans `src/**`).

### Failure modes (the ones that would matter in production)

- **A computed fact.** A renderer-local count or duration total that the JSON does not carry — the drift AD-11 exists to prevent, and it is invisible until a harness and a human disagree.
- **`error` rendered as `fail`.** Undoes the classification this whole epic is built to preserve: the operator reads "your branch is broken" when the truth is "we could not observe".
- **A flaky pass rendered clean.** FR-32's entire point is that retries are never silently optimised away. A renderer is the last place that visibility can be lost.
- **Anything but JSON on stdout under `--json`.** Breaks `JSON.parse` for every consumer — the harness contract's most brittle line, and the easiest to break with a stray debug print.
- **Unbounded output.** Floods an agent's context window; NFR-8 exists because the caller is often an agent.
- **A truncation pointer that stops working.** An absolute path breaks the moment the run directory is copied; relative paths from the run root are the requirement (Q48).
- **Colour as the only signal.** The report is read through pipes and capture buffers far more often than through a terminal.

### Security

- **Never re-redact and never reconstruct.** AD-10 puts redaction at capture precisely so a renderer cannot get it wrong; a renderer that "helpfully" re-processed text could un-redact by reformatting, or double-redact and hide real evidence.
- **Your layer rule is a security control as well as an architectural one.** A renderer that cannot import `node:fs`, `config` or `infra` cannot read a secret from disk to print it. That is why the rule is the strictest of the application layers.
- **NFR-1.** Nothing reads `~/.claude/`, `~/.codex/` or any credential store; `tests/unit/doctor/credential-boundary.test.ts` is the AST guard.
