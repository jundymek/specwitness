Clarifications (detail only, no weakening):

- **⚠️ AC1's "the criterion result derives mechanically from its assertions" is NOT YOUR CODE.** AD-13 is unambiguous and the merged code enforces it: a `SurfaceExecutor` **returns a `ProbeAttempt` and never a `CriterionStatus`** — *"there is nowhere in this interface to put one"*. The single producer is `deriveCriterionResult` in `src/domain/criterion-result.ts`, already merged, tested, and proven for the gates-only cases. **You evaluate assertions and report what you saw; something else decides what it means.** Read that module's header before writing a line: it explains that four surfaces each adjudicating status their own way would give four different answers to "did a retry that eventually passed count as flaky", and the differences would surface only as a verdict nobody could reproduce.
- **What you produce, precisely:** `ProbeAttempt {attempt, observations, assertionEvaluations, evidence, execError?, durationMs}`. Fill `assertionEvaluations` with `AssertionEvaluation {description, satisfied, expected?, actual?}` — one per assertion in the plan, **including the satisfied ones**, because FR-28 requires expected-vs-actual on non-pass results and `deriveCriterionResult` reads `find(e => !e.satisfied)` to build them.
- **AC3 IS THE CLASSIFICATION TEST AND IT IS THE MOST IMPORTANT THING IN THIS STORY.** The distinction:
  - The probe **looked and saw the wrong value** ⇒ an unsatisfied `AssertionEvaluation` ⇒ criterion `fail` (product).
  - The probe **could not look at all** — connection refused, DNS failure, socket timeout, TLS failure ⇒ **`execError: ProbeExecError {message, hint?}`** ⇒ criterion `error` ⇒ run-level `{infraError}` ⇒ exit 3.
  `outcomeOf` in the merged derivation makes `execError` outrank any assertion the probe managed to evaluate, and its comment says why: *"those assertions ran against a broken observation, so reporting `fail` from them would manufacture product evidence out of an infrastructure failure."* **A probe that could not look is not the same as a probe that looked and saw a violation, and the day those two are conflated is the day a flaky environment starts blocking mergeable branches.**
  - **Set `execError` and nothing else on that path.** Do not also emit unsatisfied assertions "for completeness" — you did not observe anything to compare.
- **AC3's test must produce the state, not mock it.** Connection-refused is easy and honest: start a fixture server, take its port, close it, then probe that port. A timeout: a fixture server that accepts the socket and never responds, with your timeout injected in milliseconds. Assert the criterion status is `error` and **not** `fail`, and that no assertion claims a product violation.
- **Q39 forecloses a tempting third option: execution-time uncertainty is `error`, NEVER `needs_human`.** There are exactly two NEEDS_HUMAN triggers, both compile-time (contract `verifiability: human`; plan `not-safely-automatable`). Nothing your executor observes can create a third.
- **⚠️ A PROBE MAY NEVER ADJUDICATE A HUMAN-VERIFIABILITY CRITERION.** `deriveCriterionResult` returns `needs_human` for `verifiability: human` **before it looks at attempts at all** — attempts do not override, unconditionally. Epic 3 caught and reverted a well-meaning "floor" variant that applied the rule only when there were no attempts; review called it a silent redesign of a recorded decision. You will not hit this if you simply never special-case it. **If you ever find yourself wanting a probe to decide a human criterion, that is an ADR in `docs/adr/`, not a branch** (Epic 3 retro §6).
- **AC1's "url against a declared service" is AD-3, and it means you never see a URL you invented.** The plan names a service id; 4.1's merged base-URL resolution turns that into a base; the plan's path is appended. **No production URL defaults; services bind to localhost unless config says otherwise.** Because `adapters-core-only` forbids `src/surfaces/**` importing `src/config/**`, the **caller resolves and passes the base URL in** — you never look it up.
- **Assertions are DATA and you evaluate them mechanically.** Status comparisons, header comparisons, JSON-path value comparisons — all driven by the plan's declarations. **Nothing is interpreted, nothing is inferred, and no AI is consulted.** "Never ask an LLM whether it passes" is the product's first non-negotiable rule.
  - **JSON-path:** keep it small and boring. A dotted path with array indices covers the ACs; a full JSONPath implementation is scope you do not need. **Whatever subset you support, the plan schema constrains it and 4.2 already decided the field's shape — read `src/schemas/plan.ts` and implement what it can express, no more.** If it can express more than you implement, that gap is a finding for your PR body.
  - **A path that does not resolve is an unsatisfied assertion with `actual` saying so — not an `execError`.** You looked; the value was absent. That is an observation about the product.
  - **A response body that is not JSON when a JSON-path assertion is declared** is a judgement call: recommendation is an unsatisfied assertion whose `actual` names the content type and the first bytes, because the server answered and the answer was wrong. State your choice in the module header and test it. (Note this is deliberately *different* from 4.5's observation-command rule, where non-JSON output is criterion `error` per Q35 — there, JSON is a contract the project owner declared; here, it is an expectation the plan asserted. Say so in your header so the asymmetry reads as a decision rather than an inconsistency.)
- **AC2 is a security exit criterion and it has a specific merged shape.** `HttpEvidence` already exists in the **closed** `EVIDENCE_KINDS` union: `{kind: 'http', request: {method, url, headers}, response: {status, headers, body: BoundedText}, capturedAt, durationMs, explanation?}`. **The `http` kind is declared and unused — you are its first producer.** Do not widen the union (that is an ADR) and do not hand-build the object: use the merged constructor, which redacts at capture.
  - **`redactHeaders` is exported from `src/domain/evidence.ts` — read it.** Authorization / Cookie / Set-Cookie are the named cases (AD-10, Q17).
  - **Bodies are bounded**: `boundedText()` redacts *and* caps at `EVIDENCE_INLINE_CAP_BYTES` (8192), with `truncationMarker()` pointing at the full file. **Read the module header's rule 2 carefully**: `redactText` does not truncate, and it exists separately because *both* copies are persistence and both must be redacted — but only one may be truncated. **A caller writing a full copy MUST pass it through `redactText` first.** The header records that exposing only `boundedText` would have left the full file carrying secrets verbatim while the seeded-secret test passed green against the inline copy — *"a test certifying a defect rather than catching it."*
  - **`{shellCommand: true}` is reserved for declared commands only.** Every byte you capture — headers, bodies, error messages — is **undeclared** (the fail-closed default). Epic 3 retro §6, and §2 observation 7 for the six leak shapes that produced the rule.
  - **The leak shape worth remembering** (retro §7): output containing `[REDACTED]` *with the secret still beside it* survives review in a way a raw leak does not. Your seeded-secret test must assert the secret is **absent**, not that `[REDACTED]` is present.
- **The URL is evidence too, and query strings carry tokens.** `?api_key=…` in a captured URL is a leak with a redacted header sitting next to it. Make sure the URL goes through redaction and test it.
- **Retries are OPT-IN, default 0 (AD-9, Q43/Q44), and orchestration is NOT yours.** `deriveCriterionResult` takes `attempts: readonly ProbeAttempt[]`, and it — not you — decides `flaky`. Its rule: **the final attempt decides**; a pass that happened *only* on retry is `flaky: true`; a run that passed then failed is a failure, not flake. Your executor executes **one** attempt per call and stamps `attempt` (1-based). Whoever orchestrates retries calls you N times. Do not loop internally.
- **HTTP client: use `fetch`.** Node ≥22.12 ships it; it needs no dependency, and the Stack table is pinned — **do not add an HTTP library**. You need a per-request timeout (`AbortSignal.timeout`) and access to response headers and the raw body text.
- **`durationMs` comes from the injected `Clock` (AD-9), never `Date.now()`.** Integer milliseconds.

### Failure modes (what "wrong" looks like here)

- **Connection-refused reported as `fail`.** A flaky environment starts blocking mergeable branches. The headline defect of this story.
- **Emitting unsatisfied assertions alongside an `execError`** — manufacturing product evidence out of an infrastructure failure.
- **A secret in the full evidence copy while the inline copy is clean.** The exact hole `redactText`'s separate existence closes, and a naive seeded-secret test passes green over it.
- **A secret in a URL query string**, next to a properly redacted header.
- **Asserting `[REDACTED]` is present** instead of asserting the secret is absent — a leak shape that survives review.
- **Retrying inside the executor.** `flaky` becomes wrong and nobody can see the attempts.
- **A hardcoded fixture port.** Fails against the concurrent auto-review run of your own suite (H-8).
- **`Date.now()`** anywhere on the path.

### Security

- Everything an HTTP response contains is **untrusted**: headers, body, and anything you echo into an error message. Redact **undeclared** — the fail-closed default. `{shellCommand: true}` is for declared commands only, and you have none.
- Redact the **URL** as well as the headers.
- Assert secrets are **absent**, not that a marker is present.
- Never read or copy `~/.claude/`, `~/.codex/` or any credential store (NFR-1).
- Never mint a `DeclaredCommand`; no escape hatch in `src/config/`.
- The epic's end-to-end seeded-secret proof is 4.7's; **your capture path's own proof is yours** (Task 4).
