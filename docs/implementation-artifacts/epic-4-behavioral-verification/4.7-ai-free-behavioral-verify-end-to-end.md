### Owner-assigned rider: Epic 3 retro debt 2 — SIGINT on the verify path (not optional)

**The verified fact:** there is **no SIGINT handling anywhere in `src/cli/` or `src/pipeline/`**. Ctrl+C during a verify tells the operator nothing about the surviving detached gate process, the worktree left on disk, or `specwitness clean`.

**What is and is not a defect, stated precisely so you do not over-fix:**

- **Exit 130 is NOT an exit-table breach.** Shell-reported signal death is distinguishable via `WIFSIGNALED`, and ADR-002's table governs *chosen* exit codes. Do not add 130 to `cli/exit.ts`.
- **The defect is the silence.** After Ctrl+C the operator has an orphaned process group and a temp worktree and no idea either exists.

**Your deliverable, in order:**

1. **Reproduce it.** Start a verify with a long-running gate or service, send SIGINT, and record what actually survives and what the operator is told.
2. **Decide the scope of the fix and state it.** Two legitimate outcomes, and **the second is acceptable**:
   - **A message on the way out**: a SIGINT handler that prints the house-style `ERROR:`/`HINT:` pair naming the run directory and `specwitness clean`, and — if it can be done safely — best-effort teardown. Beware the trap: a handler that *attempts* full async teardown and is interrupted again leaves a worse state than one that prints a reliable message. Prefer the reliable message; add teardown only if you can prove it terminates.
   - **An ADR instead.** If you conclude the fix needs signal semantics this project has not decided (re-entrancy, teardown-during-teardown, what a second Ctrl+C means), **say so in your PR body and write the ADR in `docs/adr/`** rather than inventing semantics in a branch. Epic 3's action item F names exactly this fork ("ADR or Epic 4 story"), and the retro says: *"If the agent concludes the fix needs an ADR rather than a story, it must say so in its PR body rather than inventing signal semantics."*
3. **Either way, a red-first test.** A SIGINT-during-run integration test is achievable — `tests/integration/process-lifecycle-exit.test.ts` and `process-runner-groups.test.ts` show the established patterns for signalling a child and asserting what survives.
