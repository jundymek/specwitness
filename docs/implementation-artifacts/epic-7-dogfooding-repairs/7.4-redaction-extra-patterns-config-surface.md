## The defect, in one paragraph

AD-10 makes "config-declared extra patterns" part of the redaction rule. `RedactionOptions.extraPatterns`
is threaded through the domain, the four surfaces and the authoring path, and three surface
files carry comments explaining what a project that "declares its own secrets" gets. **No
project can declare any.** There is no configuration key, and nothing at the edge ever
constructs a `RedactionOptions`, so every one of those paths receives `undefined` in
production and has done since Epic 3.

## The precedent that makes this urgent rather than tidy

`src/authoring/contract.ts:100-112` records the **same defect, already met once, in a narrower
place**. Story 6.8 gave the prompt builder a `redaction` parameter and left the entry point
without one, so — in that file's own words —

> the run's config-declared `extraPatterns` could not reach the builder from production at
> all — the parameter was reachable only from a direct builder test, which is the weakest
> possible form of "the behaviour is implemented".

A codex P1 caught it and it was fixed for the authoring path. Nobody then asked whether the
*same* was true one level up, and it was, and still is.

This is the fourth instance of one shape in this product: **D-5** (`provisionPlaywright`,
written in 5.1 and called from nowhere for two epics), **6.11** (`setup.install`, a config
surface the diagnostics validated and the pipeline never invoked), **6.8's builder parameter**
above, and this. Each survived because the only tests exercising the capability called it
themselves. That is precisely the defect class this product exists to catch in other people's
code.

## Acceptance criteria

**AC1 — a project can declare patterns.**
The Project Config schema accepts a redaction-patterns key. Invalid input is a **`ConfigError`,
which `src/cli/exit.ts:45-53` maps to exit 3**, naming the offending entry — never a crash and
never silent acceptance. Decide and document whether a bad regex is rejected or skipped; either
is defensible, silence is not.

⚠️ **NOT exit 64.** `exitCodeForError` returns `EXIT.USAGE` only for `UsageError`, which is
reserved for a malformed command invocation; every other SpecWitness error, `ConfigError`
included, returns `EXIT.INFRA`. Schema failures already raise `ConfigError`
(`src/config/errors.ts`, `src/config/load.ts`). An earlier draft of this spec required exit 64
here and was wrong — that would have forced either a special case for this one field or a
change to every configuration failure in the product. Caught by the codex review of the spec
itself.

**AC2 — a declared pattern reaches every sink that redacts.**
A declared pattern is applied wherever the built-ins are: the four surfaces, evidence
constructors before persistence, and the authoring path. Pin each with a test in which the
built-ins **cannot** match the planted secret, so the test fails if only the built-ins run.

**AC3 — the secret is absent, not merely marked.**
Every assertion checks the secret string is **absent** from the artifact, not that a redaction
marker is present (Epic 3 retro §7). A test that only looks for the marker passes against code
that prints both.

**AC4 — it reaches a persisted artifact.**
A declared pattern applies to what lands in `result.json`, not only to what reaches a terminal.
The durable artifact is the one that matters, and story 7.0 found that its two newest sinks had
been the least protected.

**AC5 — no second redaction entry point.**
`redactText` and the `domain/evidence.ts` constructors stay the only place redaction happens.
`evidence.ts:134-142` says the parameter exists precisely so no second entry point gets
invented; wiring it must not invent one.

**AC6 — a corpus fixture proves it end to end.**
A fixture whose project declares a pattern, whose run emits a matching secret, and whose
hand-written `expected.json` pins the secret **absent** from the persisted document. Seen red
before the wiring and green after — revert the edge binding, watch it fail, restore it. Quote
the red output in the PR body.

**AC7 — the comments become true.**
`browser.ts:337`, `http.ts:993`, `shell.ts:618` and `evidence.ts:134-142` describe a feature
that could not be switched on. After this story they describe what the product does. Do not
leave a comment promising what the code does not do — that is half of what kept this invisible
for four epics.

## Exact scope

**Yours:** `src/config/schema.ts` (the key); the edge wiring in **all three commands that
reach a provider or a surface** — `src/cli/commands/verify.ts`, `src/cli/commands/contract.ts`
and `src/cli/commands/plan.ts`; whatever threading is needed to reach the four surfaces and the
authoring path; the comments in AC7; the tests for all of it; and one new corpus fixture.

⚠️ **`contract` and `plan` are standalone edges and must not be forgotten.**
`src/cli/commands/contract.ts:418` calls `generateDraft` and `src/cli/commands/plan.ts:179`
calls `compilePlan`, each independently of `verify` — and **neither file contains the string
`redaction` at all** (`grep -c redaction` returns 0 for both, read this session). A project
using `specwitness contract` or `specwitness plan` would therefore still send a
custom-pattern secret to a provider, and AC2 would be satisfied on paper by wiring `verify`
alone. An earlier draft of this spec scoped only `verify.ts`; the codex review of the spec
caught it.

**Not yours:** the redaction algorithm itself, the built-in pattern set, the evidence union,
`docs/planning-artifacts/`. If the built-ins look wrong to you, report it; do not tune them
inside this story.

**If you find a defect outside this scope, REPORT IT — do not patch it.** Two of the most
valuable things in this epic so far were findings reported and deliberately left unpatched.
